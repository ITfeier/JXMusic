## 二、阻断与高危问题

### P1-1（高）音源切换 / 搜索播放的队列语义缺陷：append 而非 replace

- **位置**：
  - `lib/services/playback.dart:114-128`（`switchSource` 调用 `resolveAndPlay(...sources...)`，不传 `queue`）
  - `lib/services/playback.dart:74-97`（`playTrackGroup` 同样不传 `queue`）
  - `lib/services/playback.dart:57-68`（`resolveAndPlay`：`queue == null` 时直接 `player.playSong(playable, sources: sources)`）
  - `lib/services/player_service.dart:175-198`（`playSong`：`queue == null` 且队列里找不到该 `globalId` 时 `_queue.add(song)`，`_currentIndex = _queue.length - 1`，见 `:187-196`）
  - `lib/ui/player/player_page.dart:159-175`（音源切换按钮，HEAD `:167`）
  - `lib/ui/search_page.dart:76-79`（搜索页 `_play` → `playTrackGroup`）
  - `lib/ui/player/player_page.dart:982-1050`（队列弹层，会直接展示重复条目）
- **证据（静态推演，代码路径均可指行）**：
  1. 首页/歌单播 A → `playSong(A, queue:[...])`，队列 `[A]`；
  2. 搜索页点 B → `_play`（`search_page.dart:79`）→ `playTrackGroup` → `resolveAndPlay` 不传 queue → `playSong(B)`；B 不在队列 → `player_service.dart:193-195` 把 B **追加**到 `[A]` 末尾并切到 B；
  3. B 播完自动下一首 → 队列尾之后按列表循环回 `A`（`player_service.dart:131-150`），即 **搜索点歌播完后会跳到上一次专辑的第一首**；
  4. 若在播放页把 B 切到网易云音源：`switchSource` 同样不传 queue，B'（`globalId` 不同）再次被 append，队列变成 `[A, B, B']`，队列弹层（`:982` 起）出现同曲多平台副本，N/P 切歌会在这几条副本间跳。
- **影响**：核心播放队列状态不可信；用户可感知的错序/重复；换源后「保持进度」的意图虽实现（`playback.dart:124-126`），但代价是污染队列。属架构层「队列唯一写入口缺失」。
- **建议**：
  1. 在 `PlayerService` 增加单一写入口，例如 `playSong(..., {bool replaceCurrent = false})` 或 `replaceCurrent(Song)`：`switchSource` 必须 replace 当前条目（保持索引），不要 append；
  2. 搜索页点歌显式传 `queue: group.sources`（或 `queueMode: replace`），避免继承上一队列；
  3. `_sourcesBySong`（`player_service.dart:162`）随队列变化裁剪，避免长期累积；
  4. 修完后补最小回归测试：切源后 `queue.length` 不变、`currentIndex` 不变、`currentSong.globalId` 变为新音源。

## 三、中低危与改进项

### 中危（P2）

**P2-1（中）跨平台兜底只覆盖入口曲目，自动下一首/换源不兜底**

- 位置：`lib/services/playback.dart:22`（默认 `allowCrossPlatformFallback = true`）、`:45-53`（仅入口解析失败时才 `findAlternativeSong`）；`lib/services/player_service.dart:212-231`（`_playAt` 只用 `urlResolver`）；`lib/providers.dart:85-93`（`resolveUrl` = 单平台 `api.getPlayUrl`）；`lib/ui/playlist_detail_page.dart:52,57`、`lib/ui/home_page.dart:327-328`、`lib/ui/library_page.dart:33`、`lib/ui/my_playlist_page.dart:248,259` 均用默认 true。
- 证据：入口 A 解析失败 → 可跨平台找替代并播放（`playback.dart:45-53`）；但队列里第 2 首开始由 `_playAt` 调 `urlResolver(song)`，只请求 `song.platform` 的 `getPlayUrl`，失败即 `return`（`player_service.dart:227-231`，仅打日志）。
- 影响：「播放全部/自动下一首」只保证第一首有跨平台兜底，后续曲目 VIP/版权失败就静默停住；README:11「播放全部 + 自动下一首可连续播放」只在单平台内成立。0.9.5 并没有让它更糟（搜索页是有意收紧），但 0.9.2 的「跨平台自动替代播放」承诺容易被误读为全链路。
- 建议：在 `_playAt` 解析失败时调用 `findAlternativeSong`（或把 resolver 升级为「单平台 → 跨平台」两段）；README/CHANGELOG 明确「仅入口曲目跨平台替代」。

**P2-2（中）网易云登录态在公开接口不生效，且 `lastError`/异常契约与另两平台不一致**

- 位置：`lib/services/api/netease_api.dart:51`（`lastError => null`，恒空）、`:260-269`（`createQrLogin` 直接 `throw Exception('unikey empty')`，QQ/酷狗返回空记录 + `lastError`）、`:110-149`（`getPlayUrl` 主路径公开 GET 不带 Cookie，`:118-121`；只有 weapi 兜底 `:309-325` 带 `_cookies`）、`:58`（`_cookies` 仅用于 `_weapi`）。
- 证据：对比 QQ（`qq_api.dart:233-237` 播放请求带登录 Cookie）与酷狗（`kugou_api.dart:122-127` `_authOptions` 已接入 `getPlayUrl`）。网易云扫码登录成功后，公开搜索/公开播放接口都不带 Cookie，VIP 权益基本不参与播放路径。
- 影响：用户扫码登录网易云后，VIP 歌曲的播放成功率与未登录差异不明确；`lastError` 恒空使设置页无法展示具体失败原因（`settings_page.dart:445-455` 只能走通用文案）；`createQrLogin` 抛异常依赖 UI catch（`settings_page.dart:423-440`），与接口注释「UI 用它展示准确原因」的契约不一致。
- 建议：三平台统一「不抛异常，失败写 `lastError` 并返回空/`null`」；网易云在公开播放/搜索请求按需附加 Cookie（仅 `music.163.com` 域）；若设计上不支持网易云 VIP，请在 `docs/接口清单.md` 写明。

**P2-3（中）同一平台内 `Song.vip` 数据契约不一致（QQ/网易云歌单/榜单不填 VIP）**

- 位置：QQ：`qq_api.dart:174-192`（搜索填 `vip: payplay > 0`） vs `:331-340`（`playlistSongs` 不填）、`:363-372`（`topSongs` 不填）；网易云：`netease_api.dart:28-38`（搜索填 `fee==1||fee==4`） vs `:216-224`（`playlistSongs` 不填）、`:243-251`（`topSongs` 不填）；酷狗：`kugou_api.dart:102-113`、`:264-273`、`:296-305` 三处都填。
- 影响：`TrackGroup.primary`（`models/track_group.dart:31-41`「非 VIP 优先」）与 `allVip` 徽标只对搜索路径有效；歌单/榜单曲目的 VIP 标记恒 false，`findAlternativeSong` 的「优先免费版本」过滤（`playback.dart:159-167`）与首页 VIP 提示会失真。
- 建议：把「解析平台原始 JSON → Song」抽成单一映射函数（每个平台一个），三个入口复用，避免字段漏填。

**P2-4（中）超时/重试策略不统一，且无统一重试/取消机制**

- 证据（`grep` 全仓 timeout 结果）：
  - 全局：`lib/services/api/http.dart:7-8` `connectTimeout 10s / receiveTimeout 15s`，无重试拦截器；
  - QQ：`qq_api.dart:412`（取码 `receiveTimeout 10s`）、`:73,524-531`（兑换链总超时 20s）；
  - 酷狗：`kugou_api.dart:477-484`（`_completeLogin` 10s）；
  - 网易云：无显式超时（只吃全局 15s）；
  - UI/用例层再散落：`search_page.dart:58`（15s）、`playback.dart:158,165`（8s）。
- 影响：三平台「多久算失败」不一致；重试只存在于登录候选（QQ check_sig 3 候选、酷狗 3 套约定），搜索/播放/歌词无重试；超时后底层请求不取消（QA 报告 N2 也指出过，`docs/projects/扫码登录修复/测试报告-阶段二.md:264`）。
- 建议：`http.dart` 集中声明每类请求的 timeout 常量与 1 次幂等重试策略（下载/播放 URL 可重试，登录兑换不可），或至少在 `MusicPlatformApi` 注释里写死契约。

**P2-5（中）`lib/services/playback.dart` 分层倒挂：service 层依赖 Riverpod `WidgetRef` 与 `providers.dart`**

- 位置：`playback.dart:2`（import `flutter_riverpod`）、`:6`（import `../providers.dart`）、`:17-23`、`:74-78`、`:100-104`、`:114`（四个公开函数首参都是 `WidgetRef`）。

- 建议：把 4 个函数移到 `lib/controllers/playback_actions.dart`（或 `ui/playback/`），`services/` 只保留 `playback.dart` 中的纯函数 `findAlternativeSong`；或改成注入 `MusicApiHub + PlayerService + LibraryStore` 的普通类。

**P2-6（中）启动初始化无异常兜底**

- 位置：`lib/main.dart:13-48`：`Hive.initFlutter()` 与 4 个 `openBox`（`:18-22`）顺序 `await`，无 try/catch；`MediaKit.ensureInitialized()`（`:16`）；`windowManager.waitUntilReadyToShow`（`:33-45`）；全文件无 `runZonedGuarded`/`ErrorWidget.builder`；`lib/app.dart:24-30` 托盘初始化放在 `Future.microtask` 里（内部有 catch，但外层 async 异常无兜底）。
- 影响：任一 Hive box 损坏/权限失败 → `runApp` 不会执行，表现为黑屏/闪退且无提示；播放器构造（`PlayerService` 构造函数即 `_init()`，`player_service.dart:87`）异常会直接抛到 Provider 创建处。
- 建议：`main` 包 `try/catch` + 失败时 `runApp` 一个最小错误页（或清空损坏 box 并重启）；加 `runZonedGuarded` 记录到本地日志；Provider 创建失败给 `AsyncValue.error` 兜底。

**P2-7（中）`playSingleSource` 零调用（死代码）+ 平台标签点击语义与 CHANGELOG 有落差**

- 位置：`playback.dart:100-111` 定义；全仓 grep（`playSingleSource`）只有定义 1 处、**0 调用点**。标签点击实际走 `search_page.dart:206-207` → `_play(g, preferred: source)` → `playTrackGroup`（`playback.dart:86-95`），首个音源失败会继续试本曲目其它平台音源。
- 影响：CHANGELOG 0.9.5 写「每个平台标签都可**直接点击**播放该平台音源（不再由系统暗中挑选）」；实际是「优先该平台，失败自动换同曲其它平台并弹 SnackBar」——有利有弊，但代码里同时留了一个语义更严格的 `playSingleSource` 没人用，后续维护者会误判入口。
