## 二、修复复核（diff 逐行）

`git diff -- lib/ui/home_page.dart` 全文仅一处实质改动：

```diff
-  bool _loading = true;
+  // 初值必须是 false：initState 里的 _load() 会被 `else if (_loading) return;`
+  // 守卫拦住，若初值为 true 则首次加载永远不发起（0.9.3 引入的首页永久转圈 bug）。
+  bool _loading = false;
```

- 位置：`lib/ui/home_page.dart:24-26`；**没有其它代码改动**（`_load` 函数体、`ref.listen` 自动刷新、`_batch`/`_lastLoaded`/`_error` 均未动）。
- 首次加载链路（当前代码行号）：
  1. `initState`（`:38-41`）调用 `_load()`；
  2. `_load` 守卫（`:43-48`）：`if (nextBatch) { _batch++; } else if (_loading) { return; }` —— 初值 false → **通过**；
  3. `:49-52` `setState(_loading = true, _error = null)`（在首个 build 之前，因此首帧直接是 spinner，不会闪空内容）；
  4. 并行拉取三平台榜单（`:56-64`）+ 三平台推荐歌单（`:67-87`），`Future.wait`（`:90`），异常进 `catch` 写 `_error`（`:91-93`）；
  5. `:94-97` `if (mounted) { setState(_loading = false); _lastLoaded = DateTime.now(); }` —— 成功/失败都会退出 loading。
- **不会重复加载**：`initState` 只调一次；刷新按钮/「重试」/热门单曲「更多」都走 `_load()`（`:150,173,222,244,275` 等），受 `:46` 的 `_loading` 守卫；`:110-117` 的 60s 自动刷新额外带 `!_loading` 条件。切回首页（IndexedStack 保活，`shell_page.dart:73,85`）只在 navIndex 变为 0 时判断，`_lastLoaded` 为空或 ≥1 分钟才加载。
- 唯一无守卫路径（**既有，非本次引入**）：`nextBatch:true` 分支（`:44-45`）直接 `_batch++` 不看 `_loading`。因加载中内容区被 spinner 整体替换、按钮不可见，实际可触发窗口极窄（同帧连点），登记为低危残留（第八节 L-2）。

## 三、回归测试有效性

文件：`test/home_page_loading_test.dart`（85 行）

- 结构：`_FakePlatformApi`（空实现，`recommendPlaylists/topSongs/searchSongs…` 全部立即返回空数组）→ `_fakeHub()` 注册 platform 0/1/2 → `pumpWidget(ProviderScope(overrides: [musicHubProvider.overrideWithValue(_fakeHub())], child: MaterialApp(home: Scaffold(body: HomePage()))))`（`:68-73`）→ `await tester.pump()`（首帧）→ `await tester.pumpAndSettle()`（`:78`）→ 断言 `find.byType(CircularProgressIndicator)` findsNothing（`:82`）+ `find.textContaining('推荐歌单')` findsWidgets（`:83`）。
- **修复后（当前代码）**：测试实跑通过（`flutter test` 输出 `+4` 处的 home_page 用例，见第五节），说明 fake 数据下加载完成、spinner 消失、三个「XX音乐 · 推荐歌单」标题渲染。
- **旧代码必红（独立静态推导，未改仓库）**：`git show HEAD:lib/ui/home_page.dart` 中
  - `:24 bool _loading = true;`
  - `:36-38 initState(){ super.initState(); _load(); }`
  - `:41-48 _load()`：`nextBatch=false` → `else if (_loading) return;` **立即返回**，`_loading` 永远保持 true；
  - `:131 / :225 if (_loading)` → 始终渲染 `CircularProgressIndicator`。
  → 测试在旧代码上：spinner 持续动画使 `pumpAndSettle` 无法收敛，最终**以超时失败**（Flutter SDK 默认：`pumpAndSettle` timeout = 10 分钟，`widget_tester.dart:695`；`testWidgets` 默认测试超时同为 10 分钟，`flutter_test/lib/src/binding.dart:2240`）。即「旧代码必红」成立，监国所述「spinner 永久 + 超时」与静态推导一致。
- **断言能否区分「永久 spinner」与「加载完成」**：能——`findsNothing(spinner)` 是最直接的判据；「推荐歌单」文案是在 `else` 内容分支渲染的（`:140-200` / `:234-314`），两者互斥。
- **测试健壮性建议（不阻断）**：
  1. **失败模式慢**：旧代码要等 `pumpAndSettle` 10 分钟超时（或测试级 10 分钟）才红。建议改为有界等待，让回归「立即断言失败」：`await tester.pump(); await tester.pump(const Duration(milliseconds: 200));` 后再断言，或 `pumpAndSettle(const Duration(milliseconds: 100), EnginePhase.sendSemanticsUpdate, const Duration(seconds: 5))`。
  2. **未断言「加载确实发起」**（重要建议）：当前只验证「无 spinner + 出现标题」。若未来有人删掉 `initState` 里的 `_load()`（或让 `_loading` 永远 false 但从不请求），内容区会以空数据渲染出「推荐歌单」标题 → 测试**会误通过**。建议给 `_FakePlatformApi` 加调用计数，并断言 `topSongs`/`recommendPlaylists` 各被调用；这样「首次进入会发起加载」才被真正锁住。
  3. **依赖文案与布局分支**：`find.textContaining('推荐歌单')` 依赖中文文案；测试用默认 surface（800×600）→ `isDesktopLayout`（≥840）为 false，只覆盖**手机版**分支（桌面版 `_buildDesktop` 未被覆盖；两分支用同一 `_loading` 状态，逻辑风险低）。
  4. **未来 provider 依赖**：若页面 build 将来读取更多 provider（如 Hive 设置），ProviderScope 需同步 override，否则测试会因环境未初始化而碎。
- 结论：**对 UI-01 本缺陷回归有效**；按建议 1/2 加固后更稳。

## 七、反向检查（task 要求的两点）

1. **`ref.listen(navIndexProvider)` 在 `_lastLoaded == null` 时是否会重复触发加载？**
   - 监听在 `build` 内注册（`home_page.dart:110-117`），只在 navIndex **变化到 0** 时回调；初次注册/首帧不触发。
   - 回调条件 `next == 0 && !_loading`：首次加载进行中 `_loading=true` → 被拦；加载完成（无论成功/失败）后 `_lastLoaded` 已被赋值（`:96`），60s 内再切回不触发。
   - 因此**不会重复加载**。唯一边界：**加载失败也会更新 `_lastLoaded`**（`:94-97` 在 catch 之后仍执行）→ 失败后 60s 内切回首页不会自动重试（需点「重试」）；属**既有行为**，非本次引入（信息项 I-1）。
2. **widget 测试是否会因未来真实网络逻辑变化变脆？**
   - 已 `overrideWithValue(_fakeHub())`，不联网、不依赖平台实现细节 → 网络接口改动不影响该测试。
   - 脆弱点不在网络，而在「页面新增 provider 依赖」与「中文文案/布局分支」：见第三节 3/4，建议随手加固（不阻断）。
