### 5.1 ① 还有没有同类「先 clear 再对自身求值」写法？

### 5.2 ② 回归用例能否覆盖该路径、能否在旧代码上失败？

**能覆盖、能在「先 clear 再求值」的错误实现上失败。** 证据链：

1. 用例本身：`test/source_switch_test.dart:109-140` 用 `PlayerService(initPlayer:false)` 构造队列 `[a,b,c]`、当前索引 1，再 `playSong(target, replaceCurrent:true)`，断言 `queue.length==3`、`currentIndex==1`、`currentSong.globalId==target.globalId`、`queue[0]/[2]` 未被改。注释明确指向 `..clear()..addAll(replace(_queue))` 的历史 bug（`:131-132`）。
2. 机制验证：我用独立 Dart 片段复现了级联语义（不依赖项目代码）：

```
buggy cascade result: []  length=0
fixed style result:   [10, 99, 30]  length=3
```

即 `queue..clear()..addAll(f(queue))` 确实会先清空、再对空列表求值。若按错误实现，该用例 `queue.length==3` 第一步就失败（实际 0），`currentSong` 变 null，断言必红 → **回归有效**。
3. 补充：该用例对 **HEAD `0631a57` 的旧 `switchSource`（走 `resolveAndPlay` → 无 `replaceCurrent` 时会 append）也有效**——旧实现队列会变成 4，同样触发 `length==3` 失败。即它同时防「append 回归」和「clear 回归」。
4. 注意边界：回归用例测的是 `playSong(replaceCurrent)` 的**接法**，没有测 `switchSource` 的网络/失败分支组合（这部分只测到纯函数 `sourceSwitchError`/`canSwitchToSource`）；`switchSource` 的 await 竞态无法用当前测试发现（见问题 M-1）。

### 5.3 ③ `initPlayer:false` 测试口子是否影响业务路径？

**不影响。** 核对：

- 唯一业务构造点 `providers.dart:105-113` 未传 `initPlayer` → 默认 `true`（`player_service.dart:40,45` 才 `_init()` 创建 media_kit Player）。全仓 `PlayerService(` 仅此 1 处业务构造 + 测试 2 处。
- `initPlayer:false` 时 `_player` 为 null；`play/pause/seek/setVolume/setRate/dispose` 全部走 `_player?.` 空安全，`_playAt` 的 `_player?.open(...)` 同样空安全（`:289`）→ 不会崩。
- 口子有文档注释（`:30-31`「仅测试用」），参数可选、零行为差异；`dispose` 对 null `_player` 安全（`_player?.dispose()`）。
- 结论：可接受；建议后续若想更严格，可加 `@visibleForTesting` 注解（信息级）。

## 六、问题清单（级别 + 位置 + 证据 + 建议）

### M-1（中）切源 await 期间曲目被切换 → 会替换错曲目并 seek 旧进度

- 位置：`lib/services/playback.dart:143-204`（关键：`:145` 取 current、`:154` 取 position、`:175` `await api.getPlayUrl`、`:192-196` `playSong(replaceCurrent:true)`、`:200-202` 校验）
- 证据：`getPlayUrl` 是网络调用（`http.dart:7-8`：connect 10s / receive 15s，最坏可等十几秒）；期间用户按全局快捷键 N/P（`shortcuts.dart`，托盘菜单同理）或当前曲目自然播完触发 `_onTrackComplete`（`player_service.dart:155-174`）都会改变 `currentSong`/`_currentIndex`。`switchSource` 在 await 之后**只**校验「替换后 currentSong 是否等于目标音源」（`:200-202`，而 `replaceCurrent` 必然满足），**没有**校验「当前曲目是否仍是发起时的那一首」，也没有校验 `position` 是否属于同一首。结果：新曲目的队列项会被替换成**旧曲目的**目标平台音源并 seek 旧进度，UI 还会报「已切换成功」。
- 建议（≤3 行）：await 前记录 `current.globalId`/`currentIndex`，await 后、`playSong` 前重读 `player.currentSong` 与 `currentIndex`，不一致则直接返回失败（如「播放已切换，请重试」），不执行替换与 seek。

### L-1（低）失败原因可能使用陈旧的 `api.lastError`

- 位置：`lib/services/playback.dart:183-189`（`apiError: api.lastError`）+ `qq_api.dart:80,197`、`kugou_api.dart:41,130`
- 证据：qq/kugou 的 `_lastError` 只在**扫码链路**里赋值（qq_api 29 处、kugou_api 20 余处 set 点），`getPlayUrl`（qq_api:197 / kugou_api:130）既不读也不清 `_lastError`。若用户上次扫码失败留了「二维码已过期…」，本次播放解析失败时面板会展示这条**与播放无关**的旧错误。
- 建议：调用 `getPlayUrl` 前快照 `lastError`，仅在值变化时采用；或给接口层加 `clearLastError()`/`lastErrorForPlayback` 语义。

### L-2（低）`_switch` 无 try/catch，异常会让面板卡在「切换中」

- 位置：`lib/ui/player/player_page.dart:1118-1141`（`_switching=true` 后直接 `await switchSource(...)`，无 catch）
- 证据：若 `switchSource` 抛异常（如 provider 被销毁、`playSong` 内部未捕获路径），`:1128` 的 `mounted` 检查之后没有任何复位；`_switching` 永远 true → 面板全部行禁用 + 进度条常驻。
- 建议：`try/finally` 复位 `_switching`；异常转成面板内错误文案。

### L-3（低）面板监听整条播放器状态，位置流会让面板反复重建

- 位置：`lib/ui/player/player_page.dart:1145`（`ref.watch(playerServiceProvider)`）+ `player_service.dart:118-122`（position 每次回调都 `notifyListeners()`）
- 证据：播放中打开面板，`_posSub` 每 tick 触发 `notifyListeners`，整个 `_SourceSheet`（含 `ListView`/`ref.watch(accountProvider(...))`）重建；面板停留越久越可能掉帧（桌面影响小、低端 Android 可能可见）。
- 建议：面板只 `watch` 需要的字段（用 `ref.watch(playerServiceProvider.select(...))` 或把 current/sources 作为构造参数传入）。

### L-4（低）「需登录」徽标对所有未登录平台无条件显示，非 VIP 也标

- 位置：`lib/ui/player/player_page.dart:1264`（`if (!loggedIn) _sourceBadge('需登录', textSub)`）
- 证据：未登录时即使免费音源也会显示「需登录」，与「可能需要登录」语义不符，可能误导用户。
- 建议：改为 `if (!loggedIn && source.vip)` 或 `source.loginRequired`；免费音源不加徽标。

### L-5（低）校验只看 `currentSong`，不保证媒体真的开始播放

- 位置：`lib/services/playback.dart:200-202` + `player_service.dart:289-293`
- 证据：`_playAt` 内 `_player?.open(...)` 异常被 catch 吞掉（仅 debugPrint「播放失败」），但队列/索引已替换 → `switchSource` 仍返回 ok，UI 提示「已切换」却无声。
- 建议：让 `_playAt` 返回 bool 或暴露 `playing/error` 状态；切源成功判定加上「媒体已打开」条件（至少记录 open 异常）。

### L-6（低）切源成功会多写一条播放历史

- 位置：`player_service.dart:290`（`onSongStarted?.call(song)`）→ `providers.dart:106`（`library.addHistory` 按 `globalId` 去重）
- 证据：切源后 `globalId` 从 QQ 变成酷狗，历史会新增同曲不同平台条目；是否可接受属产品口径，建议产品确认（可改成按「歌名+歌手」去重或切源不记历史）。
