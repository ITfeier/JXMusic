### 1.3 最严重的 5 条（按危害排序）

1. **BUG-03 网易云登录态完全不进入播放链路**：扫码得到的 `MUSIC_U` 只挂在 weapi 兜底请求上，而搜索/播放/歌词主路径全是公开 GET、不带 Cookie；设置页却承诺“扫码登录，可播放 VIP 歌曲”（`lib/ui/settings_page.dart:246`）→ 登录后网易云 VIP 依然放不了，且无任何报错。
2. **BUG-04 网易云 weapi 加密实现与公开算法不一致**：随机 key 是 24 字符 base64（公开实现为 16 字符）、RSA 为无填充 raw 且未做 JSEncrypt 等价变换 → 兜底路径极可能被网易云拒绝，进一步封死网易云登录态唯一可能生效的通道（待联网实测确认）。
3. **BUG-01 播放切歌无“代次”保护**：直链解析走网络时连续切歌，多个 `_playAt` 并发 open，后完成者覆盖先完成者 → 实际音频与 `currentSong`/UI/播放历史不一致。
4. **BUG-02 播放失败全链路静默**：解析不到直链、`open` 抛异常、本地文件被删都只 `debugPrint`，`resolveAndPlay` 仍返回 `true` → UI 显示“在播”实际无声，用户只能反复点。
5. **BUG-19 + BUG-18 生命周期问题**：`ChangeNotifierProvider` 与 `ref.onDispose` 造成双重 `dispose`（debug 断言必现），且 dispose 后仍有异步歌词/切歌回调调用 `notifyListeners`。

安全侧最值得先处理：**BUG-20**（QQ/酷狗/网易云登录 cookie 明文落盘）、**BUG-21**（QQ `check_sig` 跟随 302 时把含 `p_skey` 的 Cookie 发给 Location 任意域，无白名单）、**BUG-23**（Android 全局 `usesCleartextTraffic=true` + 音频直链 http 未升级）。

### 1.4 总体判断

- 播放/下载/本地库的**主路径逻辑基本成立**，但异常路径普遍“吞错 + 状态不回收”，可观测性差；播放器状态机缺少并发保护是本层最大结构性问题。
- 三平台登录里，**QQ 链路实现最完整**（每步 lastError、候选、超时、302 手动跟随），酷狗次之（有降级），**网易云最弱（登录态无消费方、lastError 恒 null、weapi 实现存疑）**。
- 代码规范整洁（`flutter analyze lib` 零问题可解释），大量“防御性 catch”反而掩盖了失效。

## 二、确认的 Bug

> 严重级别定义：**阻断**=必现且核心功能不可用；**高**=主流程大概率触发或安全/数据严重问题；**中**=特定条件可触发、用户可感知、有绕行；**低**=边界/体验/健壮性。
> 标注「待实测」的条目表示缺陷事实来自代码静态确认，但服务端/运行期后果未联网验证。

### BUG-01 切歌并发竞态：实际音频与 currentSong/UI 不一致【高】

- **文件:行号**：`lib/services/player_service.dart:207-252`（`_playAt`，无任何请求代次标识）、`:175-198`（`playSong`）、`:131-150`（`_onTrackComplete`）、`:277-287`（`next`）
- **触发条件**：任一曲目需要网络解析直链时（`urlResolver`，`lib/services/playback.dart:155-170` 内层单请求超时 8s），用户连续点“下一首/上一首”或点另一首歌，或自动下一首与手动切歌重叠。
- **实际后果**：两次 `_playAt` 交错 await 解析与 `_player.open()`；先发起、后完成的旧请求把旧歌 open 到播放器，导致“听到的歌 ≠ `currentSong` ≠ 播放页/播放条显示”，`onSongStarted` 历史记录、歌词、音源切换按钮全部跟随错误的 `_currentIndex`。
- **修复建议**：`_playAt` 开头 `final token = ++_playToken;`，每个 await 之后 `if (token != _playToken) return;`；或在 `PlayerService` 内把播放请求串行化（`Future` 链 + 取消语义）。

### BUG-02 播放失败全链路静默，UI 误报“正在播放”【高】

- **文件:行号**：`lib/services/player_service.dart:227-231`（无直链仅 `debugPrint`+`notifyListeners` 后 return）、`:248-250`（`open` 异常仅 `debugPrint`）、`lib/services/playback.dart:54-70`（只要 URL 非空就 `return true`）、`:25-28`（本地歌曲直接播放，不校验文件存在）
- **触发条件**：CDN 403/直链过期/平台风控/本地文件被删除/解码失败（`_player.open` 抛异常）。
- **实际后果**：`resolveAndPlay` 对调用方返回 `true`，`search_page/home_page/library_page/playlist_detail_page` 都不提示失败；用户看到播放按钮状态变化但无声音，也没有任何错误原因（`BUG-02` 与 `RISK-11` 同源：`PlayerService` 无错误上报通道）。
- **修复建议**：`_playAt` 的解析失败与 open 失败返回 `false`/抛 `PlaybackException`；`resolveAndPlay` 以播放器实际 open 结果为准；本地歌曲先 `File.existsSync()`；UI 展示统一错误 SnackBar。

### BUG-03 网易云登录态不进入播放/搜索/歌词主链路【高】

- **文件:行号**：`lib/services/api/netease_api.dart:58`（`_cookies` 字段）、`:110-149`（`getPlayUrl` 公开 GET 不带 Cookie）、`:152-176`（`getLyrics` 同样）、`:61-105`（搜索同样）、`:309-326`（**只有** `_weapi` 在 `317-321` 注入 Cookie）；`lib/ui/settings_page.dart:246`（承诺可播 VIP）
- **触发条件**：用户完成网易云扫码登录后，尝试播放 VIP（`fee=1/4`）歌曲或需要登录态的高音质。
- **实际后果**：扫码得到的 `MUSIC_U/__csrf` 只用于两个兜底 weapi 请求（`getPlayUrl` 第 139 行、歌词第 170 行、搜索第 95 行），而主路径公开 GET 完全匿名；VIP 歌仍拿不到直链 → 设置页“已登录”状态与真实能力不符。
- **修复建议**：公开 GET 请求也携带 `Cookie`/`Referer`（仅限 `music.163.com`）；或修正文案、把网易云登录标注为“仅存档，暂不影响播放”。

### BUG-04 netease weapi 加密实现与公开算法存在两处偏差（待实测）【高】

- **文件:行号**：`lib/services/api/netease_crypto.dart:15-19`（`_randomKey`：16 随机字节 → `base64Encode` → **24 字符**），`:48-69`（`_rsaEncrypt`：`RSAEngine().process` = 无填充 raw RSA，且未做 JSEncrypt/公开实现里的文本反转）
- **触发条件**：任何 `_weapi` 调用（`lib/services/api/netease_api.dart:95,139,170,309-326`）。
- **实际后果**：公开可用的 weapi 实现约定为「16 字符字母数字 secKey + 反转后无填充 RSA」；当前实现两处都不符，服务端 RSA 解密得到的 key 形态/字节序与预期不一致，weapi 极可能返回错误，且错误被 `catch (_) {}` 静默吞掉（`netease_api.dart:102-104,146-148,173-175`）→ 兜底永久失效、无日志。**是否真的被服务端拒绝，需联网用固定向量实测确认。**
- **修复建议**：按公开实现修正（16 字符 alnum key、明文反转后再 modPow），并补一份“固定输入 → 固定密文”的离线单测（`kg_crypto` 已有同类测试可参考，`test/kugou_login_crypto_test.dart`）。

### BUG-05 从队列删除当前曲目/清空队列时播放状态不回收【中】

- **文件:行号**：`lib/services/player_service.dart:351-363`（`removeFromQueue`/`clearQueue`）；UI 入口 `lib/ui/player/player_page.dart:1041`（删除）、`:1050`（清空队列）
- **触发条件**：播放中打开播放页队列弹层，点当前播放项的 ×，或点“清空队列”。
- **实际后果**：删除当前项后 `_currentIndex` 不变（越界时 `currentSong==null`），但音频仍在播被删的歌 → 播放页高亮/标题与真实音频不一致；`clearQueue` 后 `currentSong` 变 null，播放页回到空 Scaffold（`player_page.dart:82-84`），音频继续播放，只能靠播放条重新操作。
- **修复建议**：删除当前项时自动播下一首或 `_player.stop()`；`clearQueue` 同时停止播放并重置 `_position/_duration`。

### BUG-06 队列缓存的直链不会失效重解析【中】

- **文件:行号**：`lib/services/player_service.dart:214-226`（仅 `audioUrl` 为空时才调 `urlResolver`）、`:222-225`（回写队列）
- **触发条件**：播放器长时间运行后重播队列中的歌（平台直链/vkey 有时效；QQ 的 `purl` 带 vkey、网易云/酷狗 CDN URL 均带有效期）。
- **实际后果**：命中旧 URL 直接 `open`，失败被 `BUG-02` 吞掉 → 这首歌从此“点了没反应”，除非重启或重新从列表播放（重新解析仍会复用带 URL 的队列项）。
- **修复建议**：解析/打开失败时清空该项 `audioUrl` 重试一次；或在队列项上记录 `resolvedAt` 做 TTL。

### BUG-07 歌词加载重复请求 + 切歌后旧歌词覆盖新歌【中】

- **文件:行号**：`lib/ui/player/player_page.dart:47-64`（1.2s 后绕过 `PlayerService` 直连 `api.getLyrics`，await 后只检查 `mounted`，不校验 `currentSong` 是否已变）；`lib/services/player_service.dart:254-267`（`_loadLyrics` 自己已有一套带 `globalId` 校验的加载）
- **触发条件**：进入播放页后 1.2s 内 PlayerService 的歌词请求尚未返回；或进入播放页后立即切歌，而页面直连的 `getLyrics` 响应晚到。
- **实际后果**：同一首歌重复两次网络请求（增加接口压力/风控概率）；晚到的旧歌歌词被 `setLyrics` 写入新歌，出现“歌是 A、词是 B”的错位，直到下一次切歌。
- **修复建议**：删除页面直连逻辑，统一由 `PlayerService` 加载；若保留，await 后校验 `ref.read(playerServiceProvider).currentSong?.globalId == song.globalId`。

### BUG-08 跨平台替代只校验标题、不校验歌手【中】

- **文件:行号**：`lib/services/playback.dart:133-174`（`findAlternativeSong`：搜索 `title artist` 后取第一个可播候选）、`:177-186`（`_similarTitle` 只归一化标题做包含判断，artist 未参与）
- **触发条件**：首页/播放入口原平台不可播、走跨平台替代（`lib/services/playback.dart:45-53`，`allowCrossPlatformFallback` 默认 true）。
- **实际后果**：同歌名不同歌手/翻唱/纯音乐版本会被当作替代音源播放（例如“晴天”“卡农”这类高频同名曲），用户听到的不是点的那首，且 UI 只提示“已改用 XX 音源播放”（`search_page.dart` 的提示逻辑只对 preferred 生效，首页/旧入口连提示都没有）。
- **修复建议**：候选需同时通过 artist 归一化包含判断（或时长差 <5s）；不满足则跳过。

### BUG-09 搜索页播放不建队列，播完即停【中】

- **文件:行号**：`lib/services/playback.dart:57-68`（`playTrackGroup` 调 `resolveAndPlay` 时未传 `queue`）、`lib/services/player_service.dart:180-198`（queue==null 时把歌 append 到旧队列）、`:131-150`（播完按旧队列/停止）；调用点 `lib/ui/search_page.dart:79`
- **触发条件**：在搜索结果里播放任意一首，等这首播完。
- **实际后果**：搜索页的播放不建立“搜索结果队列”，播完直接停（旧队列为空时），或续到历史遗留队列里毫不相干的歌；反复从搜索页播放会持续向队列 append，队列页越来越乱。
- **修复建议**：`playTrackGroup` 支持传 `queue`（搜索结果去重后的 song 列表），搜索页传入 `[for (final g in _groups) g.primary]` 之类的当前结果集。

### BUG-10 网易云 lastError 恒为 null，过期二维码不识别【中】

- **文件:行号**：`lib/services/api/netease_api.dart:49-51`（注释“保持空实现即可”）、`:272-292`（`pollQrLogin` 只在 `code==803` 返回会话，800 过期/801 等待/802 已扫全部返回 null 且不写 lastError）；UI `lib/ui/settings_page.dart:458-463`（只靠 60 次 × 2s 上限退出）
- **触发条件**：网易云二维码过期（官方 `code=800`），或登录接口返回错误码/异常。
- **实际后果**：过期后 UI 仍显示“请使用对应平台 App 扫码登录”，要等满 120 秒才提示“二维码已过期”；取码异常时 `_failHint` 只能给通用文案（`settings_page.dart:446-455`），用户无法区分风控/网络/接口变更。
- **修复建议**：`pollQrLogin`/`createQrLogin` 所有失败分支写 `_lastError`；`code==800` 时写“二维码已过期”并让对话框立即停止轮询（约定：让 UI 通过 lastError 判断终止条件）。

### BUG-11 QQ 兑换超时后结果被丢弃，迟到错误覆盖超时提示【中】

- **文件:行号**：`lib/services/api/qq_api.dart:523-536`（`.timeout(20s)`，`onTimeout` 返回 null）、`:638-781`（`_exchangeLogin` 无取消机制，内部 `:686-690,:719,:731-733,:738-739,:771-773` 继续写 `_lastError`）
- **触发条件**：扫码确认后 check_sig/authorize/QQLogin 总耗时 >20s（弱网/候选切换）。
- **实际后果**：超时提示已展示，但后台请求仍可能成功拿到 musickey（结果丢弃，用户需重新扫码）；后台失败的 `_exchangeLogin` 还会在超时之后改写 `_lastError`，把准确的“超时”覆盖成某个中间步骤的错误（会话体验不一致）。
- **修复建议**：兑换过程与 `pollQrLogin` 同生命周期加 `cancelled` 标记（酷狗 `kugou_api.dart:474-484` 已有 `isCancelled` 写法，可复用），超时后不再回写状态；或超时后保留结果并支持“继续兑换”。

### BUG-12 酷狗同一一次性 token 串行尝试三套加密约定【中】

- **文件:行号**：`lib/services/api/kugou_api.dart:499-618`（candidates 三套，`:534-608` 对同一 `token` 依次请求）、`:468-490`（外层 10s 超时）
- **触发条件**：第一套约定的请求被服务端“接受并消费 token、但响应非 status==1”或响应丢失。
- **实际后果**：第 2/3 套复用同一已消费 token 必然失败，白耗请求；10s 总超时与 3 次请求/重定向耗时叠加，可能整条补全失败。项目状态文档已承认此幂等风险（`docs/项目状态.md:66`），此处确认为代码事实：**没有换 token/重新扫码分支，也没有“首个候选返回业务错误码时停止重试”的短路**。
- **修复建议**：仅当候选返回“协议不匹配”类错误时才继续下一套；业务错误（token 无效）立即停止并提示重新扫码；把超时预算按候选数均分。

### BUG-13 下载不可取消，只能等 Dio 超时或杀进程【中】

- **文件:行号**：`lib/services/download_service.dart:110-139`（无 `CancelToken` 参数、无 cancel 方法）；UI `lib/ui/player/player_page.dart:476-481`（`barrierDismissible: false`）、`:885-931`（进度弹窗无取消按钮）
- **触发条件**：下载大文件/弱网/服务端限速时用户想取消。
- **实际后果**：弹窗不可关闭、无取消入口；若连接 stalled 则要等 Dio 全局 `receiveTimeout: 15s`（`lib/services/api/http.dart:7-8`）才失败，正常慢速下载则只能等完成；期间用户无法进行其它下载。
- **修复建议**：`DownloadService.download` 增加 `CancelToken?`，弹窗加“取消”按钮并 `cancelToken.cancel()`；失败/取消时清理半文件（见 BUG-14）。
