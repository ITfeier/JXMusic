# ADR-004：本地音乐自定义路径与加密格式解密架构

- 状态：**Accepted（v1.2）**——监国 v0.1 草案经秦（arch-review）定稿，2026-11-09；v1.1 澄清 onProgress 近似 / Flutter 依赖边界 / canDecode 调度语义；v1.2 记录 R-21 识别入口裁决，并确认 R-18/R-19/R-22/R-23 修复后回归 PASS（见 §6、评审记录 §8.8）。未改决策方向。
- 日期：2026-11-09
- 关联：`docs/projects/本地音乐与加密格式/立项单.md`、`PRD.md`、`评审记录.md`（问题清单 R-x、KGM 移植易错点 K-x、阶段二 C-x、回归 R-26）

## 1. 背景

本地音乐页当前只扫描 `defaultScanPaths()` 的第一个目录，扩展名仅 6 种，无法识别 QQ/网易云/酷狗下载的加密文件。用户要求：自定义路径 + 三平台加密格式 + 常用格式。

## 2. 决策

### D1 解密实现来源：vendored MIT 包 + 自研酷狗移植

- 网易云 NCM、QQ QMC（v1/v2，含 mflac/mgg 尾部密钥）直接 vendored 成熟 MIT 实现 `packages/music_decoder`（path 依赖），避免从零重写密码学细节。
  - 已核验：vendored 目录与 `_ref/music_decoder` 逐文件 SHA-256 一致（未改上游源码），版本 `0.1.0`，`packages/music_decoder/LICENSE` 保留 MIT 版权声明（Copyright (c) 2025 djbird2046）。
- 酷狗 KGM/KGMA/VPR：`packages/music_decoder` 不覆盖，按 `_ref/dsh-audio-converter/lib/crypto/kgm.js`（MIT）算法移植为纯 Dart 解码器，公钥表 `assets/kugou_key.bin`（8 MiB，覆盖 128 MiB 音频）随包分发。
  - 公钥表来源：`_ref/dsh-audio-converter/lib/crypto/assets/kugou_key.bin`（MIT，Copyright (c) 2026 yousj666）字节级复制，与 JXMusic 内 `assets/kugou_key.bin` SHA-256 相同（`FE2AE000…0F72A4`，8,388,608 B）；它是上游完整表（69.77 MB，覆盖约 1.1 GB 音频）解压后的**前 8 MiB**，换算覆盖 134,217,728 B（128 MiB）音频。上游再参考 `HRuiCcc/music-geshizhuanhuan` 的 `assets/kugou_key.xz`（MIT）。版权与免责文案见 `THIRD-PARTY-NOTICES.md`，核对结论见 `评审记录.md` §二。
  - 公钥表**进程内只加载一次**（解码器内部缓存 + 并发单飞）；禁止每首歌 `rootBundle.load` 一次（8 MiB 重复解码会拖慢首播并抬内存峰值）。
- 不引入新 pub 依赖（pointycastle/crypto 已有；key 表走 asset）。
- 备选：调用外部 exe/ffmpeg（不可行：Android 无 exe；APK 体积/权限风险）；纯 Dart 全自研（重复造轮子，风险高）。

### D2 统一解码器接口（`lib/services/local_formats/format_decoder.dart`）

```dart
abstract class EncryptedAudioDecoder {
  Set<String> get sourceExtensions;       // 小写、无点
  String? get outputExtension;            // 单格式返回，多格式 null
  Future<bool> canDecode(File file);      // 魔数校验
  Future<String> decodeTo(File input, File outputFile,
      {void Function(double progress)? onProgress}); // 返回输出扩展名
  Future<EncryptedAudioTags?> readTags(File file);   // 可读则读，如 NCM
}
```
- 失败统一抛 `FormatDecodeException(中文原因)`，UI 直接展示。**适配器负责把底层异常翻译成中文**：`NcmException` / `QmcException` / `QmcCipherException` / `QmcKeyDecoderException` / `FileSystemException` 一律捕获后包装，禁止把英文栈信息或底层 exception 直接透传给 UI；包装时保留原始信息到 `debugPrint`。
- 解码器不依赖 Flutter UI 层（v1.1 澄清）：解码算法与文件 IO 为纯 Dart；允许 `package:flutter/foundation.dart` 的 `debugPrint`（日志）与 KGM 默认 `rootBundle` 公钥加载器；测试必须能通过构造参数注入纯 Dart loader，从而不依赖 asset/插件。禁止依赖 widget/BuildContext/provider/riverpod。
- 契约补充（实现必须遵守，评审 R-3/R-4/R-14 依据）：
  - `canDecode` 只读判定所需的最少字节：NCM 前 8 字节魔数；KGM/VPR 前 16 字节魔数 + 文件长度 ≥ 1040；QMC 读尾部 8/4 字节与声明的 keySize。**禁止整读文件**。
  - **调度语义（v1.1 澄清）**：`LocalFormatService` 按 `sourceExtensions` 选择解码器；`canDecode` 供扫描预检与测试使用，生产播放路径不强制先调用。但 `decodeTo` **必须自行完成魔数/结构校验**，不得因扩展名匹配就盲解（实测三个解码器均满足）。
  - `decodeTo` 必须分块流式读写（建议 16 KiB 块），只允许写调用方给定的 `outputFile`，**不得自行改名/删除/移动**（缓存层的 `.part` → rename 由 `LocalFormatService` 负责）；返回**实际输出扩展名**——必须以解密产物的容器嗅探结果为准，不得按输入扩展名猜测（v1.2 澄清，对应 R-22：QMC 已删除扩展名映射 fallback，NCM/KGM 同理）。
  - `onProgress` 传 0.0–1.0，按已处理音频字节/音频总字节计算，处理完成必须回调 1.0。
  - **进度近似例外（v1.1）**：NCM/QMC 使用 vendored 包（无分块回调且**零改动**，T1 已核验），允许用「输出文件大小轮询」近似已处理字节：必须单调不减、夹取 0..1、完成补 1.0、采样异常（文件正被 rename）忽略。KGM 自研解码器必须按真实字节回调。
  - `readTags` 只解析文件头标签，**不得触发音频解密**；读不到/不支持返回 `null`，不抛异常；封面字节大小要有上限（建议 8 MiB），避免恶意/损坏文件把内存打爆。
  - **解码后自检**：QMC（尤其 musicex / STag / 无 EKey 的 v2 变体）与 KGM 解码后必须嗅探输出前 4–8 字节是否为合法音频容器（`fLaC`/`ID3`/`0xFFFx`/`OggS`/`ftyp`/`RIFF`）；不是则抛「解密结果不是有效音频…」的 `FormatDecodeException`，**禁止静默产出乱码缓存**（vendored 包在无 EKey 变体上可能"成功"返回噪声，见评审记录 R-3）。

### D3 解密编排：`LocalFormatService`（`lib/services/local_format_service.dart`）

职责：
- `isEncryptedPath(String)` / `platformLabel(String)`：按扩展名 + `LocalAudioFormats` 判断；
- `ensureDecrypted(Song, {onProgress}) -> File`：命中缓存直接返回；否则并发去重（`Map<String, Future<File>>`）流式解密到缓存，先写 `<name>.part` 再 rename；
- `playableUrl(Song) -> String?`：普通格式返回 `audioUrl`，加密格式返回缓存路径（供 player urlResolver）；失败返回 `null` 并把中文原因记到 `lastError`（供 UI/队列失败提示，评审 R-11）；
- `readTags(path)`、`saveCoverBytes(bytes)`：NCM 标签 + 封面落盘复用现有封面缓存；
- `clearCache()` / `cacheSizeBytes()` / `cacheFileCount()`：清理与占用统计入口。

缓存策略（实现按此逐条落地，评审 R-2/R-5/R-12）：
- 目录：`getApplicationSupportDirectory()/decrypted_audio/`。
- **布局**：`decrypted_audio/<keyHex>/data.<输出扩展名>`。输出扩展名只有解码完成后才知道（`decodeTo` 返回值），所以不能把扩展名编进顶层文件名；命中判定 = `<keyHex>/data.*` 存在且 `size > 0`。
- **缓存键**：`keyHex = sha1('v1|<绝对路径>|<sizeBytes>|<mtimeMs>')` 的十六进制串。
  - `v1` 是**缓存格式版本**：解码器算法/公钥表升级时递增，避免旧缓存继续命中坏产物；mtime 单位为毫秒；绝对路径与分隔符固定，PRD 中「sha1(源路径|大小|mtime)」以本条为准。
- **并发**：同一 `keyHex` 的并发请求复用同一个 `Future<File>`；无论成功失败，必须在 `finally` 中把该 key 从 map 移除（失败条目不得永久缓存，否则同一文件后续必然失败——评审 R-5）。
- **失败原子性**：先写 `data.<ext>.part`，成功后 `rename` 为最终文件；任何异常都删除 `.part` 并抛 `FormatDecodeException(中文原因)`；下次调用可重试。
- **启动清理**：初始化时清理残留 `*.part`（异常退出）与空目录。
- **淘汰**：上限 1.5 GB 或 400 个文件；播放命中时 touch（更新文件 mtime）作为访问时间，超出上限按最旧访问时间淘汰；正在解密/正在播放的条目跳过（`ensureDecrypted` 的 in-flight key 集合 + 调用方传入的「正在播放路径」）。`clearCache()` 同样跳过 in-flight 条目，返回清理字节数。

### D4 播放链路挂接

- `providers.dart`
  - `localFormatServiceProvider`：注入 `[NcmDecoder(), QmcDecoder(), KgmDecoder(pubKeyLoader: rootBundle...)]`；
  - `localMusicServiceProvider` 接收 `LocalFormatService`；
  - `playerServiceProvider.resolveUrl`：`platform == JXPlatform.local` 时走 `localFormatService.playableUrl(song)`（普通格式原样返回路径）。
- `PlayerService._playAt`：本地曲目（`JXPlatform.local`）即使 `audioUrl` 非空也调用 `urlResolver`（否则队列里的加密曲目会把密文路径直接交给 libmpv）。改动需兼容既有单测。
- **解析结果不得污染持久化曲目（评审 R-1）**：`_playAt` 现在会把 resolver 返回值写回 `_queue[index] = song.copyWith(audioUrl: url)`，并把这个 song 传给 `onSongStarted`（播放历史写入 Hive）。对本地加密曲目而言 url 是**缓存路径**，若写回队列/历史，缓存淘汰或清理后历史回放即失败，与「`Song.audioUrl` 保留源文件路径」自相矛盾。要求：
  - resolver 结果只用于 `_player.open(Media(...))`；
  - 本地曲目的队列项、`onSongStarted` 回调、历史/收藏/歌单里保留**源文件路径**（可用 runtime-only 的临时变量/映射承载解析结果，不写进 `Song.toJson()`）。
- `LocalPage._play`：加密曲目先 `await ensureDecrypted`（带进度弹窗）；失败弹窗原因；成功后用原队列调 `resolveAndPlay`。
- **队列懒解密失败必须可见（评审 R-11）**：自动下一首/播放全部时由 resolver 解密，失败若只 `debugPrint` 会重现「点了没反应」的既有 P0。resolver 失败要写入可被 UI 读取的 `lastError`（`LocalFormatService` 或 `PlayerService` 的错误状态），播放页/列表给出中文提示；不得静默把密文路径交给 libmpv。
- 本地 `Song` 的 `audioUrl` 保留**源文件路径**（历史/收藏可回放；解密由 resolver 负责），`id` 仍为 `local_<pathHash>`。
  - 已知小问题（评审 R-10，非阻断）：`pathHash = path.hashCode` 跨运行/跨平台不保证稳定，历史/收藏的 `globalId` 可能失效；后续建议改为 `sha1(绝对路径)` 的前 16 位（改时需迁移旧记录，不在 0.10.0 强制）。

### D5 多目录扫描与持久化

- `LocalMusicService.scanDirectories(List<String> paths, {onProgress}) -> ScanResult`：BFS、目录数上限、按绝对路径去重；单目录失败不影响其它目录，`ScanResult.errors` 返回 `ScanPathError{path, message(中文)}` 列表。
- 扫描细节（评审 R-6，实现按此执行）：
  - **去重键**：`p.normalize(p.absolute(path))`；Windows 再 `toLowerCase()`（大小写不敏感），Android 保持原样；多目录/重复配置都在合并后统一去重；
  - **跳过**：隐藏目录（basename 以 `.` 开头）、`Android/data`、`Android/obb`（系统数据目录，无意义且极易吃满 2000 目录上限）、`followLinks: false` 防软链环；
  - **上限**：最多 2000 个目录**按全部配置目录合计**计数（不是每目录各 2000）；
  - **不卡 UI**：目录枚举与每文件 `songFromFile` 之间 `await` 让出事件循环；每发现 N（如 20）个文件回调一次 `onProgress(found)`（进度语义是「已发现数」而非百分比）；
  - **错误隔离**：单目录 `FileSystemException`（不存在/无权限）→ 记录一条 error 继续扫其它目录；单文件解析失败 → 跳过该文件。
- 配置 `local_scan_paths`（Hive `jx_settings`，`List<String>`）；`LocalPathsStore` 封装读写、首次默认值、增删；保存前规范化路径、去重、去除不存在项（保留用户显式输入但提示不可访问）。
- 默认候选：`getExternalStorageDirectories()`、Downloads、`Music`、`/storage/emulated/0/{Music,Download,QQMusic,kgmusic/download,netease/cloudmusic/Music}`（存在才加）；Windows 用 `%USERPROFILE%\Music`。注意 Android 上 `getExternalStorageDirectories()`/`getDownloadsDirectory()` 返回的是**应用私有外部目录**而非用户音乐目录，默认值主要靠硬编码候选 + 存在性检查。
- UI：目录管理底部弹层 + 目录浏览器（`dart:io` 自绘，不引第三方 file picker）。

### D6 Android 权限

- Manifest：`MANAGE_EXTERNAL_STORAGE`（`tools:ignore="ScopedStorage"`）+ 既有 `READ_MEDIA_AUDIO`/`READ_EXTERNAL_STORAGE`（已核验 `android/app/src/main/AndroidManifest.xml` 第 8–16 行；`targetSdk` 走 Flutter 默认，当前 ≥33）。
- permission_handler：API>=30 `Permission.manageExternalStorage`，否则 `Permission.storage`；未授权显示横幅，授权后刷新。
  - 实现口径（v1.2，R-19）：checker/request **均** manageExternalStorage 优先、storage 兜底（API 30+ 上申请 storage 被系统拒绝但无害）；授权结果仍以 onResume 复核为准。
- 语义澄清（评审 R-7）：
  - 当前 targetSdk ≥33 下 `Permission.storage`（`READ_EXTERNAL_STORAGE`）**不可再申请**，任意路径扫描的唯一门禁是 `MANAGE_EXTERNAL_STORAGE`（Android 11+）；
  - `READ_MEDIA_AUDIO` 只服务于 MediaStore 类能力，**不能**作为「读任意目录」的依据（本次不用 MediaStore）；
  - `manageExternalStorage.request()` 跳系统设置后返回值不可靠，必须在 `AppLifecycleState.resumed`（或授权页返回）时重新 `status` 复核并刷新 UI，否则会出现「已授权但横幅仍在」；
  - 非 Android 平台（Windows/Web）不得调用 permission_handler，按 `defaultTargetPlatform` 直接跳过。
- 说明：本项目侧载分发，不面向 Play 商店上架；上架需改用 SAF（本次不做）。

### D7 版本与范围

- 版本 0.10.0+19；`.kgg`（KGM cryptoVersion=5）明确不支持并提示；musicex 尾部失败按解密失败处理。
- **`.kgg` 必须可被扫描识别**（评审 R-16）：当前 `LocalAudioFormats.encryptedExtensions` 未含 `kgg`，会导致用户放的 `.kgg` 在列表里彻底消失、无法给出「需要客户端密钥，暂不支持离线解密」的提示，与立项单「识别后给出明确提示，不崩溃」不一致。要求（Lead 改契约文件）：`encryptedExtensions` 加入 `kgg`（platformLabel → `酷狗加密`），且 `KgmDecoder.sourceExtensions` 含 `kgg`/`canDecode` 认 KGM/VPR magic，`decodeTo` 在 `cryptoVersion==5` 时抛统一中文原因。
- musicex 口径：vendored 包对 musicex（mflac/mgg 尾部 `musicex\0`）会盲解整文件、不保证是真 flac；**必须执行 D2「解码后自检」**，产物不是合法音频容器即抛「QQ 音乐 musicex 尾部不含密钥，暂不支持离线解密」，不做「看起来能播」的乱码输出。
- **识别入口裁决（R-21，v1.2）**：加密格式识别入口为**扩展名**（与用户实际文件命名一致），**不做**「无扩展名/错误扩展名的主动魔数识别」；解码前由 `canDecode`/`decodeTo` 内校验魔数与尾部结构，扩展名与内容不符时明确报错。NCM 魔数 `CTENFDAM`，KGM/VPR 前 16 字节 magic，QMC 以扩展名 + 尾部结构判断。PRD REQ-3 已同步修订；该类改名文件视为用户改名/损坏场景，由解密失败提示兜底。
- 不解密/不导出源文件，缓存只进应用目录。

## 4. 失败语义

| 场景 | 行为 |
|---|---|
| 扩展名是加密格式但解密器不认 | `FormatDecodeException('无法识别的 <格式> 加密文件')`，列表标红，点击弹原因 |
| `.kgg`（含 cryptoVersion==5） | `FormatDecodeException('酷狗 KGG 格式需要客户端密钥，暂不支持离线解密')`；扫描列表可见但标「暂不支持」 |
| QQ musicex / STag / 无 EKey 的 v2 尾部 | `FormatDecodeException('QQ 音乐该文件尾部不含密钥（musicex/STag），暂不支持离线解密')`；禁止输出乱码缓存 |
| 解码后不是合法音频容器 | `FormatDecodeException('解密结果不是有效音频（文件可能已损坏或为不支持的变体）')` |
| 文件截断/密钥损坏 | 明确「文件不完整或密钥损坏」，删除半截缓存 |
| 酷狗音频超过公钥表覆盖（>128 MiB） | 「文件过大，超出酷狗公钥表覆盖范围」 |
| 酷狗公钥表缺失/asset 加载失败 | 「酷狗公钥表缺失（assets/kugou_key.bin），无法解密」 |
| 缓存目录不可写/磁盘不足 | 「解密缓存写入失败：<原因>」，删除 `.part`，不产生半截文件 |
| 本地曲目缺少源文件路径 | 「本地文件路径缺失，无法解密播放」 |
| 目录不存在/无权限 | 该目录错误条目（中文原因），不中断其它目录扫描 |
| 队列懒解密失败 | resolver 返回 null + 记录 `lastError`，UI 提示；不得静默交给 libmpv |

## 5. 后果

- 正向：双端统一纯 Dart 实现；缓存后二次播放快；失败可解释。
- 负向：APK +8 MB（key 表）；首扫大目录耗时长；首次解密耗时（大 FLAC 数秒）；QMC musicex/`.kgg` 覆盖有限，需文档说明。
- 安全/合规：仅本机解密用户自有文件，不提供下载/分享能力；参考实现许可（MIT）在 `packages/music_decoder/LICENSE` 与 `THIRD-PARTY-NOTICES.md` 保留（公钥表来源、哈希与文案核对见 `评审记录.md` §二）。
