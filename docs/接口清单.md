# 接口清单与失效替换指引

> 本项目使用各平台公开/逆向接口，官方可能随时调整。本文档记录**每一类接口的当前实现位置、候选与替换方式**；
> 接口失效时只改对应一个文件即可，无需动业务逻辑。

最后更新：2026-11-08（v0.8.0+8）

## 五、接口失效后的标准处理流程

1. 看 `lastError` 文案 / `tool/check_*.dart` 探测脚本输出，判断是「网络 / 风控 / 接口变更」哪类。
2. 在浏览器或用 `curl` 复现该请求，确认状态码与响应体。
3. 只改对应 API 文件里的 URL 常量与参数 map（本文档第一节~第三节）。
4. 用对应 `tool/check_*.dart` 验证取码/轮询/搜索等最小闭环。
5. 更新本清单与 `CHANGELOG.md`，跑 `flutter analyze lib` + `flutter test`，提交。
