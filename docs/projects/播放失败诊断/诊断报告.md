## 1. 结论摘要

**结论一句话：用户看到的「部分音乐无法播放」主要是 A 类（权限墙：未登录 → VIP/付费歌拿不到直链），且未登录态下 9/9 的 vip 样本 100% 被判为权限受限；B 类（与登录无关）在本轮样本里表现为两类：QQ「节目」类免费内容无 vkey（接口级），以及《森林之心》从历史记录回放时停在 00:00（新解析直链与 CDN 正常，但历史持久化的旧 audioUrl 未排除；open 层候选 ①历史旧直链失效 ②播放器解码/状态机）。**

实测数字（主矩阵 18 首 = 三平台各 3 首免费 + 3 首 VIP）：

| 平台 | free 可播 | vip 可播 | 失败根因（vip 3 首） |
|:--|:--:|:--:|:--|
| QQ音乐 | 3/3 = 100% | 0/3 = 0% | `result=104003`，purl 为空（缺播放票据/权限受限）×3 |
| 网易云 | 3/3 = 100% | 0/3 = 0% | `data[0].code=-110`，url 为空（需登录）×3 |
| 酷狗 | 3/3 = 100% | 0/3 = 0% | `error="需要付费"` + 兜底 `err_code=30020` ×3 |
| **合计** | **9/9 = 100%** | **0/9 = 0%** | **A 类 9/9（接口级直接证据）** |

- 主矩阵 A 类 9 首、B 类 0 首、可播 9 首（L0185）。
- 额外样本 3 首（不计入成功率）：《森林之心》**新解析**直链+CDN 正常（L0142–L0147）；但它是从**历史记录回放**，app 优先使用历史里持久化的旧 `audioUrl`（`playback.dart:81-88`、`song.dart:78`、`library_store.dart:94-97`），因此**未排除旧直链失效**，归入 B 类“播放器/open 层（候选①旧直链失效 ②解码/状态机）”；QQ 节目类免费内容 2 首 → B 类“非登录的内容限制”（L0139–L0156，L0186）。
- 无效随机 `MUSIC_U` 对照 2 例：与不登录完全相同的 `code=200 / data[0].code=-110`，说明无效会话不获得任何播放权限（L0078–L0084、L0109–L0113）。
- 跨平台兜底实验 11 次（9 个 A 类 + 2 个节目 B 类）：11/11 都能在其它平台找到“标题相似的非 VIP 候选且 getPlayUrl 有直链”（L0087、L0098、L0100、L0115、L0124、L0126、L0137、L0138、L0141、L0151、L0158）。这意味着 A 类歌在 app 的 `resolveAndPlay` 自动兜底路径下**可能被换成 Live/Demo/翻唱版本播出来**，用户感知可能是“放出来的不是我要的版本/时好时坏”，而不是纯黑屏失败。
- **第二轮（用户样本 7 Years，§9）**：网易云《7 Years》Lukas Graham（id=405599119，vip=true）未登录 `itemCode=-110`、url 空（L0213）→ **A 类**；按 app 同逻辑兜底，QQ 原版（vip）被跳过，会选中 **QQ「7 Years (T-Mass Remix)」**（L0224–L0232）。主矩阵 9 首 A 类 VIP 歌的兜底去向按「会不会换版本」分类：**9/9 都会换版本**（Live/Demo/翻唱/30s 或 50s 片段，L0282–L0396）。
- **第三轮（登录后对照，§10）**：从模拟器已登录 App 的 Hive 取出真实网易云会话（7 个 cookie，MUSIC_U len=802，证据打码 L0406）注入探针；账号接口 `vipType=0`（有效会话、非会员，L0407）。同一批 4 首 VIP **0 首可播**（4/4 仍失败），接口码与未登录完全相同（`itemCode=-110`、`fee=1`、url 空：L0411/L0420/L0429/L0435）；免费对照《屋顶》仍 OK（L0440–L0443）。**结论：登录 ≠ 会员，-110 是会员权益墙，不是“没登录”专属。**

**对用户怀疑的回应：账号无法登录确实是主因（A 类，100% 复现于 VIP 样本）；但更准确地说，是「登录态 + VIP/付费权益」这道墙——补上登录后，非会员账号对 VIP 歌仍然是 -110。同时“部分音乐无法播放”里还混着与登录无关的 B 类问题（播放器层静默失败、换版本兜底），需要分别处理。**

## 2. A 类 / B 类的判定口径

探针为每首样本记录两级证据：**应用层**（`api.getPlayUrl` 返回值、`api.lastError`）与**接口层原始响应**（HTTP 状态、响应 JSON 的 code/msg、purl/url 是否为空），拿到直链后再做 **CDN Range 前 4KB 探测**（HTTP 状态、content-type、字节数、音频魔数）。

判定标签（探针 `L0008` 有同文定义）：

| 标签 | 含义 |
|:--|:--|
| `OK` | 有直链，且 Range 探测返回 200/206 + 音频魔数（ID3/fLaC/OggS/ftyp/MPEG 帧同步）+ content-type 非 html/json |
| `A_LOGIN_DIRECT` | 接口直接返回登录/权限码（如网易云 `-110`） |
| `A_PAID_PERMISSION` | 接口直接返回付费/会员权限错误（如酷狗 `需要付费` / `err_code=30020`） |
| `A_RESTRICTED_CODE` | 接口权限受限业务码（QQ `result=104003`，缺播放票据） |
| `A_LIKELY_PERMISSION` | 推断：vip 曲无直链且同平台免费样本可解析（本轮未用到） |
| `B_NO_DIRECT_URL` | 接口 200 但无直链（版权/下架/内容类型限制/接口契约） |
| `B_CDN_REJECT` | 拿到直链但 CDN 拒绝或返回非音频（本轮 0 例） |
| `B_INTERFACE` | HTTP/网络/解析错误（本轮 0 例） |

**判定不靠猜**：每条 A 类结论都对应原始响应里的 code/msg/业务码（§5 摘录），B 类同理；`api.lastError` 在全部 21 个样本里均为空串——这是另一个可观测缺口（见 §8 第 4 条）。

> 第三轮登录后对照补充：`-110` 在**已登录的非会员账号**下仍原样返回（L0411），因此 A 类更准确的叫法是「登录态 + VIP/会员权益墙」，而不只是“未登录”。免费档（fee=8）在未登录与已登录下都返回 200 + url（L0045、L0442）。

## 8. 代码路径核对（诊断结论与 app 实际行为对齐）

1. 网易云 `getPlayUrl`：公开 GET 拿 url，空则 weapi 兜底（`lib/services/api/netease_api.dart:258-304`）；实测 `-110` 与注释“VIP fee=1 返回 code=-110 需登录”一致（`:263-266`）。

## 10. 登录后对照（模拟器已登录网易云会话注入）

### 10.0 授权与合规声明（如实记录）

- **授权来源**：本节会话注入由监国（lead）在本次会话中**明确追加授权**（2026-11-09 19:05 左右，指令要旨：「从模拟器 emulator-5554 已登录的 App 里取出网易云会话，注入探针验证登录后 VIP 歌能不能播；cookie 只在系统临时目录、输出打码」）。
- **与 task-1 原文的关系**：task-1 原写「不得使用任何真实账号凭据」；本节是在该任务完成后的**后续专项指令**下进行，后续指令显式覆盖原限制，故此处如实记录授权链，便于审计追溯。
- **账号归属与用途**：使用模拟器上用户本人已登录的网易云会话；用途**仅限诊断**（验证“登录 ≠ 会员”）。
- **边界**：不写仓库、不写证据原文、不绕过付费/破解、不修改 App、不代替用户做任何账号操作；cookie 只在探针内存与系统临时目录使用，诊断结束后临时文件已删除。

### 10.1 会话来源与安全处理

- emulator-5554 的 adbd 可用 root（`adb shell id` → uid=0）；从 `/data/data/com.jxmusic.jxmusic/app_flutter/jx_accounts.hive`（1551B，18:53 写入）读出账号 box（Hive 二进制按 4 字节长度前缀解析出 cookies map）。
- 取到 **7 个 cookie**：`MUSIC_A_T, MUSIC_R_T, MUSIC_R_U, MUSIC_SNS, MUSIC_U, NMTID, __csrf`；`MUSIC_U len=802`（与监国实扫证据的 len=802 一致）。
- **敏感数据纪律**：cookie 只存在于系统临时目录 JSON 与探针内存；**不写入仓库、不写入本 evidence**；证据只记录 **cookie 名 + 长度**（`MUSIC_U(len=802)`、`__csrf(len=32)`，L0406），**不记录任何值片段**（QA P1 修复：此前版本曾输出首 4/末 4 片段，已重跑替换）。

### 10.4 结论（对“是不是登录问题”的最终回答）

**是“登录 + 会员权益”问题，不是单纯“没登录”：**
1. 未登录 → 网易云 VIP 歌 `-110`、直链空（首轮结论成立）。
2. **已登录但非会员（vipType=0）→ VIP 歌仍 `-110`、直链空，与未登录完全相同**（§10.3）。
3. 免费档（fee=8）登录前后都可播（L0045、L0442）→ 会话注入本身有效，不是注入姿势问题。
4. 因此 `-110` 的语义应表述为「需要 VIP/会员权益（或该账号无该曲版权）」，而不是“未登录”；对用户要说明：**登录只解决会话，会员/付费才解决 VIP 曲**。

### 10.5 限制

- 只验证了**一个网易云非会员账号**；未验证会员账号、也未验证 QQ/酷狗登录后的表现。
- cookie 提取依赖 emulator adbd=root（用户镜像但 adbd 已 root 的特殊环境），**真机不可用**；因此该对照只能作为「登录≠会员」的接口级证据，不能作为交付功能。
- 注入仅发生在探针进程内（`NeteaseApi.restoreSession`），未修改 App、未写入仓库。

## 11. 限制与假设（必须与结论一起看）

1. **真实账号范围**：第三轮已注入**一个真实网易云非会员账号**（vipType=0），证明“登录后仍 -110”；但**未验证会员账号**、未验证 QQ/酷狗登录后的表现，也未验证“登录+会员”能否真正拿到 VIP 直链。酷狗 `需要付费` 可能要求付费购买而非会员；QQ `104003` 需登录后拿到 `qqCookiePlaybackKey` 播放票据（该码语义引用第三方公开文档旁证：<https://raw.githubusercontent.com/Yyyangshenghao/simple-music/master/docs/qq-music-api.md>，非官方文档）。真实解锁率须靠后续会员账号 + 真机复跑验收。
2. **`docs/ARCHITECTURE.md` 不存在**（任务必读清单中的该文件缺失，工作区 `docs/` 只有 `接口清单.md`、`项目状态.md`、`审计/`、`projects/`）；本轮以 `docs/审计/架构审计.md` 与源码阅读替代，架构理解未见矛盾。
3. **工作副本含并行会话未提交改动**（`git status`：`lib/services/api/netease_api.dart`、`qq_api.dart` 等）；探针以工作副本为准。已核对：QQ 的 `getPlayUrl` 相对 HEAD 无改动（`git diff -U2` 的 hunk 不覆盖该函数）；网易云只在 `_cookies` 非空时新增 `Cookie` 请求头，未登录态不生效。故不影响“未登录态”结论。
4. **网络环境**：本次实测网络很快（首轮约 5 秒、第二轮约 11 秒、第三轮约 3 秒），早前“粗探针 7 分钟未返回”未复现；可能是网络抖动或对端风控。探针仍保留了 600s 全局预算与逐请求超时，便于慢网复跑。

7. **无效 MUSIC_U 语义**：随机 32 hex 只是“无效会话”，证明无效态无权限；现已用真实会话补测（§10），无效会话与真实非会员会话返回相同（-110）。

## 12. 建议（本轮不改代码，供后续立项）

1. **A 类（P0，主因）**：已用真实非会员会话验证「登录后仍 -110」（§10），因此产品侧要把文案拆成“需登录”与“需会员/VIP 权益”两种；后续用**会员账号**复跑 `--case=third-round`（把 `JX_COOKIE_FILE` 换成会员会话即可），确认会员后直链与 CDN；重点检查：网易云 `MUSIC_U` 是否被 getPlayUrl 携带（工作副本已加 Cookie 头）、QQ 登录后是否拿到 `qqCookiePlaybackKey`/`musicid/musickey`、酷狗 `login_by_token_get` 补全是否带上会员权益 cookie。
2. **B 类-播放层静默失败（P0/P1，需单独立项）**：《7 Years》现场（§9.1：AudioTrack 0 frames、自动跳下一首、UI 无提示）与《森林之心》（§5.5：历史回放旧 audioUrl 未排除、新解析直链/CDN 正常）指向同一层：解析/CDN 正常但 media_kit/libmpv → AudioTrack 没出声。`player_service.dart` 未监听 `stream.error`、`open` 异常仅 `debugPrint`（`:292-294`）、无直链仅 `debugPrint`（`:271-275`）；需专项抓 mpv/ffmpeg 日志、在 mpv 里直接打开同一 QQ m4a URL 对照、检查 headers/UA/重定向/封装；同时验证历史持久化旧直链是否过期（`playback.dart:81-88`）。
3. **静默兜底与 UI 提示（P1）**：`resolveAndPlay` 跨平台兜底成功后只有 `debugPrint`（`playback.dart:99-100`）；搜索页会提示“已改用 X 音源播放”（`search_page.dart:87-89`），但歌单/首页/音乐库路径（`playlist_detail_page.dart:75-84`、`home_page.dart:358-365`）没有任何提示。建议在歌单/首页也提示，并加“优先当前平台音源 / 不跨平台替换”开关。
4. **B 类-兜底版本错乱（P1）**：`findAlternativeSong` 只校验标题相似，实测 9/9 换成 Live/Demo/DJ/翻唱/30s 或 50s 片段（§9.5）。建议加歌手匹配、时长容差（拒绝 <45s 或时长差 >15s）、版本关键字降权，并对“换版本播放”给明确提示。
5. **A 类体验补丁（P1）**：`getPlayUrl` 失败时把接口可观测原因写入 `api.lastError`（如“VIP 需会员”“需要付费”），让播放页/音源面板文案从“可能需要登录或受版权限制”变成确定原因（当前 21/21 样本 lastError 为空）。
6. **B 类-内容（P2）**：QQ 节目/电台类（vip=false 但 `104003`）应在 UI 明确“该内容不支持播放”，不要落入通用“需要登录/版权”文案。
7. **诊断常态化（P2）**：把 `tool/check_play_matrix.dart`（主矩阵 + `--case=second-round/third-round`）纳入发布前手动检查（类似 `docs/项目状态.md` §三 的联网手动检查列表）；登录/会员修复后用同一脚本做前后对照。
8. **敏感数据（持续纪律）**：会话 cookie 只允许在临时目录/内存用于诊断，不进仓库、不进证据原文；本轮证据已按 cookie 名 + 打码长度记录（L0406）。
