## 三、KGM 算法移植核对（`kgm.js` → Dart，供 T2 自查）

### 3.1 文件结构与参数

| 字段 | 偏移/长度 | 说明 |
|---|---|---|
| magic | `[0,16)` | KGM = `7c d5 32 eb 86 02 7f 4b a8 af a6 8e 0f ff 99 14`；VPR = `05 28 bc 96 e9 e4 5a 43 91 aa bd d0 7a f5 36 31`；`.kgma` 用 KGM magic（以 magic 为准，不看扩展名） |
| audioOffset | `[0x10,0x14)` LE32 | 音频起始偏移，必须 ≥1024 且 < 文件长度 |
| cryptoVersion | `[0x14,0x18)` LE32 | `==5` 即 KGG，离线无解；其余按本文算法解 |
| crypto_test | `[0x1c,0x2c)` 16 B | 作为私钥前 16 字节 |
| ownKey | 17 B | `crypto_test || 0x00`（第 17 字节恒 0） |
| pubKey | 每块 1 B | `assets/kugou_key.bin`；8 MiB 表覆盖 134,217,728 B 音频 |

### 3.2 等价性推导（评审已暴力验证 p<2,000,000 无差异）

设 `p` = **音频数据内**字节序号（0 起，已扣除 audioOffset），`b = p ~/ 16`，`c = p % 16`，`phase = b % 17`：

- `ownIdx = (phase*16 + c) % 17` **等价于** `p % 17`。
  证明：`p = 16b + c ≡ -b + c (mod 17)`；`phase*16 + c = 16(b mod 17) + c ≡ 16b + c ≡ p (mod 17)`。
- `pubIdx = (phase*16 + c) % 272` **等价于** `p % 272`。
  因为 `phase*16 + c ≤ 16*16+15 = 271 < 272`，且 `16b ≡ 16(b mod 17) (mod 272)`（272=16×17）。
- `pubValue = pubKey[b]`（**块**序号，不是字节序号）。
- `scramble(v) = (v ^ ((v & 0x0F) << 4)) & 0xFF`，**自逆**（`scramble(scramble(v)) == v`，全 256 值成立）。
- 解密：`plain[p] = scramble(cipher[p] ^ ownKey[p % 17]) ^ scramble(pubKey[p ~/ 16] ^ MEND[p % 272])`
- 加密（构造测试样本/往返验证）：`cipher[p] = scramble(plain[p] ^ xormask) ^ ownKey[p % 17]`，其中 `xormask = scramble(pubKey[p ~/ 16] ^ MEND[p % 272])`。
- `MEND_TABLE` 272 字节常量（与 `kgm-py` 交叉一致），首 4 字节 `b8 d5 3d b2`。

### 3.4 与 `_ref/kgm-py` 的差异（不要照抄 Python）

| 项 | kgm.js（移植以此为准） | kgm-py | 影响 |
|---|---|---|---|
| header 校验 | 只校验前 16 B magic；offset/version 动态读 | `startswith` 28 B 固定前缀（offset 必须 1024、version 必须 3、0x18 必须 1） | 照抄 Python 会**错误拒绝** version 4/其它 offset 的真实文件 |
| audioOffset | 读 0x10 并按它定位音频 | 固定跳到 1024 | 照抄会解错位（真实文件 offset 可能 >1024） |
| `scramble` | `& 0xff` | 未 mask（Python 恰好不越界） | Dart 必须 `& 0xFF`（int 为 64 位） |
| pubKey 长度校验 | `blockCount > pubKey.length` 抛错 | 启动时校验 xz 解压长度 | Dart 保留按文件校验 |

### 3.5 易错点清单（K-1..K-22，T2 逐条自查）

| 编号 | 易错点 | 正确做法 |
|---|---|---|
| K-1 | 用**文件绝对块序号**算 phase：audioOffset=1024 是 16 的倍数但**不是 17 的倍数**（1024/16=64，64 mod 17 = **13**），文件块号会比音频块号错位 13 | phase 必须用音频数据内块号 `b = 音频字节位置 ~/ 16` |
| K-2 | ownKey 只取 16 B 忘记追加 `0x00`，或用 `[0x1c,0x30)` 多读 4 B | `header[0x1c..0x2c)` + 1 个 `0x00`，共 17 B |
| K-3 | ownIdx 写成 `(phase*17+col)%17` / `col % 17` / `b % 17` | `(phase*16+col) % 17`，等价 `p % 17` |
| K-4 | MEND 表长度/索引错（写成 256、`b % 272`、或 `(phase*16+col)%17`） | MEND 272 B，索引 `p % 272` |
| K-5 | pubValue 用 `pubKey[p]`（字节序号） | `pubKey[p ~/ 16]`（块序号） |
| K-6 | scramble 写成 `v ^ ((v & 0xF0) >> 4)`（方向反）；或漏 `& 0xFF` | `(v ^ ((v & 0x0F) << 4)) & 0xFF` |
| K-7 | 解密公式项顺序/位置错：先 scramble ownKey 再 XOR、或 `scramble(pubValue) ^ MEND` | `scramble(cipher ^ ownKey[idx]) ^ scramble(pubValue ^ MEND[idx])` |
| K-8 | 分块流式时每个 chunk 从 0 重算 phase/块号 | 维护跨 chunk 的全局音频字节偏移 `processed`，块号 = `(processed+i) ~/ 16` |
| K-9 | 块内 `col` 用 chunk 内 `%16`（chunk 大小非 16 倍数时错位） | `col = (processed + i) % 16`，或固定 chunk 为 16 倍数（建议 16 KiB） |
| K-10 | 进度分母用 `file.length`（含 1024 header）→ 永远到不了 1.0 | 分母 = `fileLength - audioOffset`；完成必须 `onProgress(1.0)` |
| K-11 | 公钥上限比较写反：`blockCount >= pubKey.length`、或拿字节数比（`audioLength > pubKey.length`） | `blockCount = ceil(audioLength/16)`；`blockCount > pubKey.length` 才报错 |
| K-12 | cryptoVersion 读 `0x18`（那是别的字段） | 读 `[0x14,0x18)` LE32；`==5` 抛 KGG 中文错误 |
| K-13 | `canDecode` 只认 KGM magic，漏 VPR；或 `.kgma` 单独 magic（不存在） | 同时认 KGM/VPR 两个 16 B magic；`.kgma` 按 magic 判 |
| K-14 | `canDecode` 整读大文件 | 只读 16 B magic + 取 `file.length()`；长度 <1040 直接 false |
| K-15 | 输出格式在**解密前**嗅探、或读整文件嗅探 | 解密后只读输出前 64 B 嗅探：`fLaC`/`ID3`/`0xFF 0xF1`/`0xFF 0xF9`/`OggS`/`ftyp`/`RIFF` |
| K-16 | 空音频/音频长度为 0 当成功（offset == fileLength） | `audioOffset >= fileLength` 或 `audioLength == 0` → 「文件不完整或密钥损坏」 |
| K-17 | 最后一块不足 16 B 未裁剪（越界/多写） | `end = min(start+16, audioLength)`，只处理实际字节 |
| K-18 | 测试样本「加密」用了错误的逆公式导致「解回来正好抵消」，什么都没验证 | 用 §3.3 黄金向量断言真实明文；往返测试只作补充 |
| K-19 | 公钥表每首歌 `rootBundle.load` 一次 | 构造器注入 loader + 实例内缓存 + 并发单飞（R-8） |
| K-20 | 公钥表缺失/读取失败把 `FlutterError`/`FileSystemException` 裸抛 | 包装 `FormatDecodeException('酷狗公钥表缺失（assets/kugou_key.bin），无法解密')` |
| K-21 | 真实 `assets/kugou_key.bin` 在测试里按相对路径读取，换工作目录即崩 | 测试文件缺失时 `skip` 并打印原因；优先用 `File('assets/kugou_key.bin')`；E2E 由 QA 覆盖 |
| K-22 | 忘记 `& 0xFF` 后把 >255 的值写入 `Uint8List`（Dart 会截断但中间运算语义易错）；或 `Uint8List` 直接用 `List<int>` 加法 | 每步取 `& 0xFF`；用 `Uint8List`/`ByteData` |

### 8.5 与「接口契约」的偏差结论

1. **`canDecode` 不在生产调度中调用**：ADR v1.1 已澄清调度改为「按 sourceExtensions 选解码器 + `decodeTo` 自校验」；实测三个解码器 `decodeTo` 均先校验（NCM 调自身 canDecode + 头部解析、QMC 尾部结构、KGM magic/长度/版本），无「扩展名匹配即盲解」。判 **PASS（契约已修订）**，不要求改代码。
