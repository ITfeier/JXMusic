# 立项单：本地音乐自定义路径 + 三大平台加密格式支持

- 立项日期：2026-11-09
- 提出人：用户（截图：Android 本地音乐页空态「未发现音乐文件」）
- 负责人：监国（Team Lead）；PRD 由监国代拟（本次范围明确，未单独召集唐）
- 版本目标：0.10.0+19

## 一、目标

1. **自定义音乐路径**：本地音乐页支持添加/删除多个自定义扫描目录，持久化，重启保留，多目录合并去重扫描。
2. **三大平台加密格式**：扫描识别并解密播放
   - 网易云：`.ncm`
   - QQ 音乐：`.qmc0/.qmc2/.qmc3/.qmcflac/.qmcogg/.mflac/.mflac0/.mgg/.mgg1/.bkcmp3/.bkcflac/.tkm`
   - 酷狗：`.kgm/.kgma/.vpr`
3. **常用格式**：mp3/flac/m4a/aac/ogg/opus/wav/wma/ape/aiff/dsf/mka 等直接扫描播放。

## 二、不做什么（本次明确排除）

- 不解密 `.kgg`（酷狗 cryptoVersion==5，密钥在客户端密钥库，离线无解）——识别后给出明确提示，不崩溃。
- 不做批量导出/转码/写标签到源文件（解密结果只进应用缓存）。
- 不做 Android MediaStore 系统媒体库集成（仍走文件路径 + 全部文件访问权限）。
- 不承诺 QQ `musicex` 新版尾部 100% 可解（失败给原因，不静默）。
- 不动登录/在线播放/歌单等既有链路（除本地歌曲播放解析挂接点）。

## 三、平台

- Android（主要验收平台，模拟器 E2E + APK 交付）
- Windows（同一套 Dart 实现，静态分析 + 单测覆盖；不单独做 UI 自动化）

## 五、关键风险与对策

| 风险 | 对策 |
|---|---|
| QMC v2（mflac/mgg）需要文件尾部密钥派生（TEA-CBC），合成样本需实现加密侧 | 使用 MIT 参考实现 `music_decoder` 直接 vendored；测试实现 TEA-CBC 加密侧做端到端回环 |
| 酷狗 KGM 需要 8MB 公钥表，覆盖 128MB 音频 | 作为 asset 打包（+8MB APK）；超长音频失败给明确提示；`.kgg` 明确不支持 |
| 真实版权样本不可公开分发 | 合成样本验证算法闭环；真实文件由用户/QA 手动验收；报告标注覆盖边界 |
| Android 11+ 受限存储 | 声明 `MANAGE_EXTERNAL_STORAGE`，permission_handler 跳转授权；未授权时给出横幅 |
| 解密大文件卡 UI | 分块流式解密 + 缓存；解密过程带进度；扫描时只读 NCM 元数据，QMC/KGM 懒解密 |
| 既有 116+ 测试回归 | 改动集中在本地音乐链路；QA 跑全量门禁，非作者评审 |
