# 立项单 · 歌词展示修复 + 播放页黑胶圆盘

- 立项日期：2026-11-10
- 负责人：监国（Lead）
- 版本：0.10.1（本轮）
- 关联任务：T1 歌词数据层 / T2 播放页 UI / T3 质量门禁与验收

## 一、背景与问题现象

用户反馈（2026-11-09）：**「软件歌词功能无法展示」**，并要求**把方形的封面图片改成圆形的黑胶光盘外观**。

现场核查（2026-11-10，监国）：

1. 播放页歌词入口存在：`lib/ui/player/player_page.dart` 的「歌词/专辑」切换按钮 → `_LyricsView`。
2. 歌词数据链路存在：`PlayerService.lyricsResolver` → 各平台 `getLyrics` → `LyricParser.parseLrc`。
3. **已定位硬伤（QQ 平台歌词 100% 为空）**：`lib/services/api/qq_api.dart:331-343` 的
   `getLyrics` 请求 `c.y.qq.com/lyric/fcgi-bin/fcg_query_lyric_new.fcg` 时**没有带
   `Referer: https://y.qq.com/`**，而 `JXHttp` 全局默认 Referer 是 `music.163.com`。
   用与 App 完全一致的请求头实测：
   - 不带/带 music.163.com Referer → `{"retcode":-1310,"subcode":-1310}`（歌词为空）
   - 带 `Referer: https://y.qq.com/` → `retcode:0` + 完整 LRC
   网易云 `/api/song/lyric` 与酷狗 `krcs→lyrics` 两条链路实测正常。
4. 播放页歌词只有「空/有」两态：加载期间显示「暂无歌词」，接口失败静默成空、无重试
   （既有审计 UI-17）；`player_page.dart` 另有 1.2s 延迟直连歌词请求，与服务层重复。
5. 播放页大封面是方形圆角图（`_GlowCover`），用户要求改为圆形黑胶唱片外观。
6. `LyricParser` 对 1 位小数时间戳（`[mm:ss.f]`）毫秒换算错误（审计已记录）。

结论：**不是「功能没做」，而是 QQ 歌词请求缺 Referer（主因）+ 歌词缺少加载/失败态**
导致用户只见「暂无歌词」。

## 二、目标

1. 三个平台（QQ/网易云/酷狗）播放歌曲时，歌词能稳定加载并在播放页展示、跟随进度高亮滚动。
2. 歌词具备「加载中 / 无歌词 / 加载失败可重试」三态，不再误导用户。
3. 播放页方形大封面改为**圆形黑胶唱片**外观：黑色盘体 + 沟槽纹理 + 中心圆形封面标签 +
   中心轴孔，播放时转动、暂停时停住。
4. 质量门禁全绿（analyze/test/build），有独立 QA 验收报告。

## 四、不做什么（本轮范围外）

- 桌面歌词、悬浮歌词、锁屏歌词、逐字歌词（KRC 逐字）。
- 歌词翻译/音译双语显示。
- 全局缩略图圆形化（列表/播放条迷你封面保持方形圆角，控制信息密度）。
- 下载/收藏/歌单等其它功能。
- Android 真机/模拟器实机复测（模拟器当前 offline；Windows 端真实运行验证为主）。

## 五、技术栈与平台

- Flutter 3.47.8 / Dart 3.13.7，单工程双端（Windows + Android）。
- 改动仅 Dart 层，无新增依赖。
- 验证环境：Windows 10/11 + 本机 Flutter SDK 副本（见 `docs/projects/歌词与黑胶改造/环境说明.md`）。

## 六、风险与限制

1. **平台接口随时可能变**：QQ 歌词 Referer 规则为 2026-11 实测口径；若再变，按同一处配置改。
2. **本会话 shell 无法直接走系统 TLS**（Schannel 被沙箱限制），但 Dart/Python 的自带 TLS 可用；
   Android 模拟器 offline，因此**验收以 Windows 真实运行 + 接口探测 + 单测为主**，Android 仅做构建校验。
3. 黑胶外观属于视觉主观项，验收以「圆形、黑胶质感、可旋转、不溢出、不破坏既有交互」为准。
4. 歌词为网络异步数据：极端弱网下必须有 loading/error 态，不能白屏或永远「暂无歌词」。
