# 立项单 · 手机端顶部安全区适配（v0.10.1）

- 立项日期：2026-11-09
- 监国：lead
- 编队：监国 + 宋（实现）+ 清（测试与准入）
- 基线：`main` @ 工作树 0.10.0+19（上一轮本地音乐/加密格式未提交改动，先做基线提交）

## 一、问题（用户原话）

> 「ui设计顶部超出通知栏了，需要修改一下要适配主流手机屏幕尺寸」

即：Android 手机端顶部内容（标题/搜索框等）被状态栏（通知栏）压住或重叠，需要按主流手机
屏幕尺寸做安全区适配。

## 二、根因（监国初判，待实现方核实）

1. `android/app/build.gradle.kts` 使用 `flutter.targetSdkVersion`，实测已装包 `targetSdk=36`
   → Android 15/16 强制 edge-to-edge，Flutter 首帧即全屏绘制，状态栏区域由应用自行避让。
2. `lib/ui/shell_page.dart` 手机版布局为 `Column(IndexedStack(五个 tab 页), PlayerBar, TabBar)`，
   只有底部 TabBar 包了 `SafeArea(top:false)`；五个 tab 页（首页/搜索/音乐库/本地/设置）顶部
   各自硬编码 `padding.top = 14~20`，没有任何 `SafeArea`/`MediaQuery.padding.top` 避让
   → 内容画到状态栏/刘海下面。
3. 全工程没有设置 `SystemUiOverlayStyle` / `SystemChrome.setEnabledSystemUIMode`：
   浅色主题下状态栏图标可能不可见（深色图标未声明）。

## 三、目标（可验收）

- G1：手机端所有主页面顶部内容（文字/按钮/输入框）完整显示在状态栏/刘海/挖孔下方，不重叠、不被裁切。
- G2：主流手机屏幕尺寸下无布局溢出、无内容被系统栏遮挡：
  - 竖屏：320×568、360×640、360×780/800、393×852、412×915（dp）
  - 横屏：640×360、915×412
  - 状态栏安全区：24dp（普通）、32/36dp（刘海/挖孔）、48dp（大屏/平板）
- G3：浅色/深色主题下状态栏图标清晰可见（浅底深图标 / 深底浅图标）。
- G4：Windows 桌面布局（宽度 ≥840dp）行为与现在完全一致，无回归。
- G5：`flutter analyze lib` 无问题；`flutter test --no-pub` 全绿（含新增安全区用例）。

## 四、不做什么

- 不做平板/折叠屏专属双栏布局；不改视觉风格（Liquid Glass）；
- 不改 Windows 自绘标题栏、迷你模式；
- 不重构播放器/接口层；不新增第三方依赖（能用 Flutter 内置能力就用内置）。

## 五、技术边界

- 安全区适配集中在 `lib/ui/`（手机端壳层 + 需要补齐的页面/弹层）；
- 状态栏样式统一在 `lib/app.dart` 或 `lib/main.dart` 一处声明，按主题亮度切换；
- 只在 `!isDesktopLayout` / Android 路径生效，桌面端不受影响；
- 新增回归测试 `test/top_safe_area_test.dart`（实现方）+ `test/top_safe_area_acceptance_test.dart`（QA 独立用例）。

## 六、验收方式（证据要求）

1. widget 测试：模拟 `MediaQuery.padding.top`（0/24/36/48dp）与主流宽度（320/360/393/412dp），
   断言各 tab 首个可交互内容 `globalTop >= padding.top`，且无 `RenderFlex overflow` 异常；
   **修复前该测试必须为红（失败），修复后为绿**（先复现后修）。
2. Android 真机/模拟器：构建 release APK 安装到 `127.0.0.1:16384`，用 `adb shell wm size/density`
   切换主流尺寸，逐页 `screencap` 截图，状态栏区域不得出现被压住的标题/搜索框。
3. 门禁：`flutter analyze --no-pub lib` + `flutter test --no-pub` 输出原文；桌面尺寸回归用例通过。
4. 非作者评审：清 审 `lib/` diff 与测试报告，出发布准入结论。

## 七、风险

- 设备是 MuMu/小米模拟器（1080×1920@480 = 360×640dp），`wm size` 改分辨率可能与模拟器窗口不匹配，
  截图需核对 `dumpsys window` 的有效显示区域；
- `flutter build apk` 依赖 Gradle 与签名配置，网络不稳（pub 需 `--offline`）；
- 页面顶部硬编码 padding 较多，改 SafeArea 后可能出现「双重留白」，需肉眼核对截图；
- 上一轮 0.10.0 改动未提交，需先做基线提交，避免与本次修复混在同一 diff。
