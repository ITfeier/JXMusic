- 结论：**已根治**。手机端顶部安全区改由壳层 `MobileShellBody` 统一避让一次

## 一、根因（引用基线 `8b736fe` 行号）

### 1. Android 强制 edge-to-edge，但界面没有做顶部避让

`git grep -n -E 'SystemUiOverlayStyle|setEnabledSystemUIMode|SystemChrome' 8b736fe -- lib`
**输出为空**（无任何系统栏/edge-to-edge 调用）。而 `android/app/build.gradle.kts`
使用 `flutter.targetSdkVersion`，实测安装包 `targetSdk=36` → Android 15/16 强制
edge-to-edge：界面从屏幕 (0,0) 起绘制，状态栏/刘海/挖孔区域必须由 App 自己避让。

### 2. 手机版壳层只避让底部，顶部完全没有避让

基线 `lib/ui/shell_page.dart:114-126`：

```dart
: Column(
    children: [
      Expanded(
        child: IndexedStack(index: index, children: pages),   // ← 顶部无 SafeArea
      ),
      const PlayerBar(),
      _MobileTabBar(...),                                     // ← 内部才有 SafeArea(top:false)
    ],
  ),
```

只有底部 `_MobileTabBar`（基线 `shell_page.dart:409-410`）包了 `SafeArea(top: false)`。

### 3. 五个 tab 页顶部各自硬编码 14~20dp，与状态栏重叠

| 文件（基线行号） | 代码 | 顶部值 |
|---|---|---|
| `lib/ui/home_page.dart:383` | `const EdgeInsets.fromLTRB(16, 14, 16, 10)` | 14dp |
| `lib/ui/search_page.dart:109` | `const EdgeInsets.fromLTRB(16, 16, 16, 10)` | 16dp |
| `lib/ui/library_page.dart:129` | `const EdgeInsets.fromLTRB(20, 18, 16, 10)` | 18dp |
| `lib/ui/local_page.dart:385` | `const EdgeInsets.fromLTRB(20, 20, 16, 4)` | 20dp |
| `lib/ui/settings_page.dart:30` | `const EdgeInsets.fromLTRB(16, 20, 16, 30)` | 20dp |

→ 状态栏 24/36/48dp 时，标题/搜索框的 globalTop = 14~20dp，直接落在状态栏区域内
（修复前 widget 测试实测：16.5 / 17 / 18 / 20dp）。

### 4. 状态栏图标颜色未声明

全工程无 `SystemUiOverlayStyle`。浅色主题（默认 `darkMode=true` 可切换为浅色）下
状态栏图标为系统默认，可能看不清。

## 二、修复方案

### 1. 手机端壳层统一避让一次（根治，不逐页打补丁）

`lib/ui/layout.dart` 新增公开容器与工具（`layout.dart:15/27/50`）：

- `kJxMobilePageTopGap = 10`：安全区之下的统一呼吸间距（单一来源）；
- `MobilePageSafeArea`：手机端内容区安全区容器
  - 顶部 `SafeArea(top: true)` 避开状态栏/刘海/挖孔，再追加 10dp；
  - 左右 `left/right: true` 避开横屏挖孔/手势区（竖屏通常为 0，不影响布局）；
  - 底部 `bottom: false`：底部保持现状，仍由 `PlayerBar` / `_MobileTabBar` 各自处理；
  - **桌面布局（宽度 >= 840dp）原样返回 child，零变化**（G4）。
- `jxPageTopInset(context, desktop: X)`：页面顶部内边距，手机端返回 0（因为安全区已在
  壳层避让），桌面端返回各页原值。

`lib/ui/shell_page.dart` 手机分支改为公开的 `MobileShellBody`（`shell_page.dart:129`），
内容区包一层 `MobilePageSafeArea`（`shell_page.dart:155`）：

```dart
Column(
  children: [
    Expanded(child: MobilePageSafeArea(child: IndexedStack(index: index, children: pages))),
    playerBar,                       // 默认 const PlayerBar()，测试可注入空壳
    _MobileTabBar(index: index, navItems: navItems, onTap: onTap),
  ],
)
```

五个 tab 页改为 `jxPageTopInset(...)`（手机端 0 / 桌面端保持原值），
从而消除「安全区 + 页面硬编码 padding」的双重留白：

- `lib/ui/home_page.dart`：手机版头部顶部 14 → 0（安全区由壳层给）；
- `lib/ui/search_page.dart:133` 附近：桌面 16 / 手机 0；
- `lib/ui/library_page.dart:133`：桌面 18 / 手机 0；
- `lib/ui/local_page.dart`：桌面 20 / 手机 0；
- `lib/ui/settings_page.dart`：ListVIew 顶部 桌面 20 / 手机 0。

### 2. 状态栏样式统一（G3）

- `lib/app.dart:55`：`MaterialApp.builder` 里用 `AnnotatedRegion<SystemUiOverlayStyle>`
  包住全局内容，值来自 `jxSystemUiOverlayStyle(dark:)`（`app.dart:94`）：
  状态栏/导航栏透明 + 浅色主题深色图标 / 深色主题浅色图标，
  `systemStatusBarContrastEnforced/systemNavigationBarContrastEnforced = false`；
- `lib/main.dart:24`：仅 Android（`isAndroid` = `!kIsWeb && Platform.isAndroid`，
  `main.dart:15`）显式 `SystemChrome.setEnabledSystemUIMode(SystemUiMode.edgeToEdge)`，
  表达「App 主动选择 edge-to-edge」；Windows 桌面完全不执行。
- Flutter 3.47.8 下这些 API 无弃用告警（`flutter analyze --no-pub lib` → No issues）。

### 3. 顺带根治的两处既有布局溢出（验收用例暴露，不是本次改动引入）

1. `lib/ui/library_page.dart:509`（`_EmptyHint`）：空态 `Center(Padding(Column))` 在
   640x360 横屏 + 迷你播放条 + 底部 Tab（内容区仅约 166dp）时溢出 **66px**
   （QA 用例实测 `A RenderFlex overflowed by 66 pixels on the bottom`，creator 链为
   `Column ← Padding ← Center ← _EmptyHint ← Expanded ← Column ← LibraryPage`）。
   改为 `Center(SingleChildScrollView(...))`：常规屏居中不变，矮屏可滚动。
2. `lib/ui/shell_page.dart:390`（桌面 `_DesktopTopBar` 搜索框）：固定 220dp 宽，
   等宽/异体字体或系统字体放大时 `Row` 溢出 **8.5px**（QA 用例在测试字体下暴露）。
   给文案加 `Flexible + maxLines:1 + ellipsis`：放得下时渲染与改动前完全一致，
   放不下时省略而不是画出屏幕。

### 4. 修复过程中发现的前置缺陷（同属 lib/，一并修）

`lib/providers.dart` 原来同时写了 `ref.onDispose(store.dispose)` / `ref.onDispose(service.dispose)`，
而 riverpod 2.6.1 的 `ChangeNotifierProvider` 在 provider 释放时会**自动** dispose notifier
（见 `flutter_riverpod-2.6.1/lib/src/change_notifier_provider/base.dart:226-238`），
导致二次 dispose，debug/测试下抛 `A LibraryStore was used after being disposed.`
（任何 pump `LibraryPage` 的 widget 测试在 teardown 必现）。已删除这两处冗余调用
（`providers.dart:84`、`providers.dart:138` 有注释说明）。**行为不变**：riverpod 仍会 dispose。

## 七、给清（QA）的诊断：`top_safe_area_acceptance_test.dart` 当前残留失败

> 说明：该文件是清 的独立用例，我**只读、未改动**。以下为本次顺手运行的实测诊断，
> 供 QA 修用例时参考（两轮迭代：8 失败 → 2 失败 → 1 失败，其中 640x360 空态 66px 溢出已于
> 4.x 节修复）。

### 7.1 `G2 横屏 640x360dp`：`Found 0 widgets with type "TextField"`（用例问题）

用例在「五页循环」结束后（此时 `navIndexProvider = 4`，即设置页）再找
`find.descendant(of: find.byType(SearchPage), matching: find.byType(TextField))`。
`IndexedStack` 只把**当前选中页**挂载/布局，非选中页对默认 finder
（`skipOffstage: true`）不可见 → 搜索框找不到（报 0 个）。
建议：检查搜索框前先 `_switchTab(tester, container, 1)`，或在 finder 上加
`skipOffstage: false`。

### 7.2 `G4 桌面 1280x820dp`：`IconData(U+F013D)`（= `Icons.search_rounded`）出现在 x=1016.5dp（用例问题）

该断言要求「导航图标只在左侧侧栏（x < 120dp）」。但 1280dp 桌面布局的顶部工具条里
**本来就有搜索框图标**（`shell_page.dart` `_DesktopTopBar`，右侧 x≈1016dp），
它是桌面设计的一部分，不是手机版底部 Tab。
建议：把断言限定为「5 个导航图标」且排除 `Icons.search_rounded`，或只检查
侧栏子树（例如 `find.descendant(of: <sidebar>, ...)`）。

### 7.3 已由实现侧修掉的两条（复跑应转绿）

- `320x568 padding.top=24/36/48dp / 设置 存在被整体挤出屏幕的内容`：
  该断言 `rects.every((r) => r.top < screenHeight)` 会把 SettingsPage `ListView`
  在 cacheExtent 内**屏幕下方已布局但未显示**的子项也算进来（实测被判定项为
  `top=570.0` 的托盘说明文字，而此时 ListView 视口为 `Rect.fromLTRB(0, 34, 320, 398)`——
  它在视口下方，属正常可滚动内容，不是「被挤出屏幕」）。建议只对「当前可见」子项或用
  视口 rect 做边界。
- 640x360 音乐库 66px 溢出、桌面顶栏 8.5px 溢出：已在实现侧修复（第二节 3），用例应转绿。
