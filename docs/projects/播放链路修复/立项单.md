# 立项单：播放链路缺陷修复（0.9.9）

- 立项日期：2026-11-09
- 负责人：监国（lead）；实现：宋（song）；独立验收：清（qing）
- 基线版本：0.9.8+17（2026-11-09 02:27 构建）

## 一、目标

修复用户真机/模拟器反馈的三处缺陷，让「歌单详情 → 播放 → 迷你播放器」与「热歌榜 → 更多」两条核心链路可用。

## 二、缺陷与验收口径

| 编号 | 现象（用户原话） | 根因（已实证） | 验收标准 |
|:--|:--|:--|:--|
| D1 | 歌单有了但是里面没有音乐（截图：QQ 歌单「甜度爆表｜旋律说唱狙击少女心」显示 0 首、列表空白） | QQ `playlistSongs` 请求未带 `Referer: https://y.qq.com/`，被全局默认 `music.163.com` 影响，QQ 返回空 songlist（同一 disstid：163 Referer→0 首，y.qq.com→66 首）；另歌单头部写死 `p.songCount`（QQ 广场恒 0） | 该歌单详情加载出实际歌曲（66 首）；头部显示实际首数、不显示「0 首」；空歌单有明确空态与重试 |
| D2 | 酷狗音乐的歌单点击播放，播放器在下方无法显示 | `PlayerBar` 只挂在 ShellPage；歌单详情/我的歌单是 push 的整页路由，把底部播放条盖住 | 歌单详情页、我的歌单详情页底部出现迷你播放条（歌曲/歌手/播放键），点击可进播放页；360x640dp 无溢出 |
| D3 | 热歌榜点击更多无法展开 | `JXSectionHeader(onMore: _load)` 只是重新加载首页，不展开；桌面「热门单曲」同样 | 点「更多 ›」内联展开全部已加载榜单（不重新请求、不闪 loading），按钮变「收起 ›」，可再次收起 |

## 三、不做什么

- 不做歌单详情分页/懒加载（当前接口一次可取全量，超出 100 首另立项）。
- 不重构 PlayerBar 为全局 overlay（本轮只在两个详情页补挂，降低回归面）。
- 不改三平台其他接口、不改播放引擎、不动 UI 视觉风格。
- 不含 QQ/酷狗 VIP 登录态与付费播放链路（另有阻塞项）。

## 四、验证方式

- `flutter analyze --no-pub lib` 零问题；`flutter test` 全绿（新增 3 类 widget 用例）。
- `flutter build apk --release --no-pub` 产出 APK；模拟器 emulator-5554 上按 D1/D2/D3 逐项 E2E 截图（清独立执行，不许采信作者汇报）。
- 回归：首页加载、搜索、播放页、Shell 底部播放条。

## 五、风险

- 平台接口对 Referer/参数敏感，可能随时再变：请求头集中写、接口失效按 `docs/接口清单.md` 替换。
- 详情页新增 PlayerBar 占用底部高度，矮屏（360x640）需布局测试兜底。
- 内联展开后列表变长，仅移动端实际验证；桌面布局以 widget 测试 + 手测抽样覆盖。
